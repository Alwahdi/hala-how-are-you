# خطة: دخول برقم الجوال + أول إضافة راوتر بأسهل طريقة

## الرحلة كما يراها صاحب الشبكة
```text
1) رقم الجوال  →  2) رمز WhatsApp (6 أرقام)  →  3) Google أو البريد  →  4) أول راوتر
```
- **شاشة 1:** حقل واحد كبير لرقم الجوال مع علم الدولة (اليمن افتراضياً، مصر وسوريا جاهزة)، لصق دولي يعمل، أيقونة WhatsApp واضحة. زر واحد: «أرسل الرمز».
- **شاشة 2:** 6 خانات للرمز، تعبئة تلقائية من الحافظة، عداد إعادة إرسال (60 ثانية)، رابط «غيّر الرقم».
- **شاشة 3:** زر Google بشكله الرسمي، أو البريد وكلمة المرور (دخول/إنشاء في نفس الشاشة). يُربط الرقم المؤكد بالحساب.
- **شريط تقدم** أعلى الشاشات (1 من 3) وزر رجوع في كل خطوة، عربي/إنجليزي كامل، أرقام 0–9.
- المستخدم العائد: إذا رقمه مؤكد سابقاً يدخل مباشرة بـ Google/البريد بدون رمز.

## أول دخول: معالج «أضف راوترك الأول»
بدل صفحة فارغة، شاشة ترحيب ثم 3 خطوات بأيقونات:
1. **الاسم والإصدار:** اسم الراوتر + اختيار v7 / v6 ببطاقتين كبيرتين (مع تلميح «كيف أعرف إصداري؟»).
2. **طريقة الربط** ببطاقتين واضحتين:
   - **أمر لصق (موصى به):** يعمل حتى لو الإنترنت خلف CGNAT. ننسخ أمراً واحداً يُلصق في Terminal.
   - **IP Cloud / DDNS:** للشبكات التي لها عنوان مفتوح. يدخل اسم IP Cloud (مثل `xxxx.sn.mynetname.net`) ومستخدم قراءة فقط ننشئ له أمراً جاهزاً. نجرّب الاتصال فوراً؛ إن فشل (CGNAT أو منفذ مغلق) نقترح أمر اللصق بضغطة.
3. **انتظار الاتصال:** دائرة حية «ننتظر أول رسالة من راوترك...»، تتحول لعلامة صح مع اسم الراوتر وCPU والوقت، ثم «اذهب لراوتراتي».
- زر «سأكمل لاحقاً» دائماً متاح؛ ومن صفحة راوتراتي يُفتح نفس المعالج.

## ما يحتاجه منك قبل التشغيل الفعلي
- **ربط WhatsApp Business** عبر الموصل (رقم أعمال + موافقة Meta، قد تأخذ دقائق).
- **قالب رمز تحقق** يحتاج موافقة Meta (حتى 48 ساعة) قبل أن تصل الرموز لأي رقم. رسائل التحقق مدفوعة لكل رسالة حسب تسعير Meta للدولة.
- حتى الموافقة: الشاشات تعمل، والإرسال يُظهر رسالة واضحة «خدمة الرمز قيد التفعيل».

## المخاطر والحدود (بصدق)
- IP Cloud لا يعمل خلف CGNAT، ويتطلب فتح منفذ API في الراوتر وتخزين مستخدم قراءة فقط مشفراً لدينا — هذا يوسّع سطح الهجوم؛ لذلك القراءة فقط، منفذ مشفر (API-SSL)، وتحذير بتقييد المنفذ.
- v6 عبر IP Cloud يستخدم API (منفذ 8729)، وv7 يمكنه REST؛ اختبار حقيقي على راوترَيك مطلوب قبل الإعلان عنه.
- لا نطلب كلمة مرور المدير أبداً.

## التفاصيل التقنية
- قاعدة البيانات: جدول `profiles` (رقم الجوال المؤكد، وقت التأكيد، اللغة) وجدول `phone_otps` (رقم، hash الرمز، انتهاء 10 دقائق، محاولات ≤5، حد إرسال لكل رقم وعنوان) بدون سياسات قراءة للزوار. أعمدة جديدة في `routers`: `connection_method` (push | ip_cloud)، `cloud_host`، `api_user`، `api_secret_encrypted`، `last_check_error`.
- خادم: دوال `sendPhoneCode` و`verifyPhoneCode` (WhatsApp عبر الموصل، قالب AUTHENTICATION)، رمز مؤقت موقّع يثبت التحقق ويُربط بالحساب بعد الدخول؛ `testIpCloud` و`pollIpCloudRouter` (TCP عبر Workers أو REST HTTPS) يكتب نفس شكل الحالة في `last_status` لتظهر بنفس البطاقات. تشفير السر بمفتاح مولّد في الأسرار.
- واجهة: إعادة كتابة `/auth` كمعالج خطوات، مسار جديد `/_authenticated/onboarding` للمعالج، توجيه أول دخول بلا راوترات إليه، إعادة استخدام مكون إضافة الراوتر في صفحة راوتراتي.
- قرار جديد D-030 في docs، وتحديث status وroadmap. اختبارات: صلاحية الرمز وانتهاؤه وحد المحاولات، تحقق الرقم الدولي، اختيار طريقة الربط.
