# هوية المنتج أولاً، ثم صفحة الهبوط

## الهدف
تأسيس هوية واضحة لمنتج مستقل تحت شركة **Alwahdi**، ثم تصميم صفحة هبوط صادقة تناسب مرحلة ما قبل إطلاق الميزة الأولى. هذا مسار محدود لا يعني اكتمال الاستكشاف أو اعتماد بناء المنصة.

## التوصية لهدف الصفحة
**طلب وصول مبكر** الآن، بدلاً من «جرّب الآن» قبل وجود تجربة تعمل. يصبح الإجراء تجربة مباشرة بعد جاهزية أول ميزة والتحقق منها. طلب الوصول إشارة اهتمام، لا دليل شراء.

## المرحلة الأولى: أساس العلامة والاسم
- مراجعة الرؤية والقرارات وبحث المنافسين القائم، دون إعادة البحث كله.
- صياغة موجز يحدد الجمهور الأول، المشكلة التي نخاطبها، الوعد الواقعي، التميز، وشخصية المنتج؛ لا ندعي أتمتة أو توافقاً مثبتاً قبل الاختبار.
- بحث أسماء قصيرة قابلة للنطق والكتابة بالعربية والإنجليزية، مستقلة عن اسم الشركة وتسمح بالتوسع.
- التحقق عبر الويب من استخدام كل اسم في المجال قبل عرضه، مع بيان نتائج البحث وحدودها. فحص استخدام الاسم أو النطاق لا يمنح ضماناً قانونياً للعلامة.
- عرض قائمة قصيرة بأسباب الاختيار والقيود، وتحديد كيفية ظهور «من Alwahdi» بجانب اسم المنتج.

**بوابة اعتماد:** يختار المؤسس الاسم والتموضع قبل تطوير الهوية النهائية. لا شراء نطاق أو تسجيل علامة ضمن هذه الخطة.

## المرحلة الثانية: النبرة والهوية البصرية
- إعداد مبادئ نبرة عربية وإنجليزية مع أمثلة للعناوين والأزرار والأخطاء والأسعار؛ واضحة، عملية، بلا مبالغة أو لوم للمستخدم.
- عرض اتجاهين بصريين مختلفين ومبررين: ألوان، خطوط عربية/لاتينية، توجه الشعار، وأسلوب الصور والأيقونات.
- اختبار قراءة الاسم والألوان والتباين والخطوط على الهاتف، وملاءمة RTL/LTR.
- بعد اختيار الاتجاه، إعداد الشعار واستخداماته الأساسية وقواعد الحجم والمساحة المحيطة والنسخ الملائمة للخلفيات.

**بوابة اعتماد:** يعتمد المؤسس النبرة والاتجاه البصري قبل تطبيقهما في الصفحة؛ اعتماد الخطة ليس اختياراً تلقائياً للألوان أو الخطوط.

## المرحلة الثالثة: نظام التصميم وموجز الصفحة
- تعريف قواعد الألوان والخطوط والمقاسات والمسافات والتخطيط والأيقونات والحركة وإتاحة الاستخدام.
- تحديد حالات الأزرار والحقول والتنبيهات والتحميل والنجاح والخطأ؛ يوضع الأساس للصفحة دون تصميم جميع شاشات المنصة.
- إعداد نص وترتيب الصفحة: اسم المنتج ووعده الواقعي، المشكلة والنتيجة المقترحة، أمثلة بصرية مصرح بأنها تصورية إن لم تكن من منتج فعلي، حالة التطوير، صلة المنتج بالشركة، أسئلة شائعة، وطلب الوصول المبكر.
- لا أرقام عملاء أو شهادات أو أسعار أو صور منتج جاهز مخترعة، ولا مزايا غير مبنية توصف بأنها متاحة.
- تحديد أقل بيانات لازمة لطلب الوصول، والخصوصية والموافقة وسياسة الاحتفاظ وطريقة متابعة الطلبات، قبل جمع أي بيانات.

**المخرج:** دليل هوية، أساس نظام تصميم، ونص ومخطط صفحة للمراجعة.

## المرحلة الرابعة: تنفيذ صفحة الهبوط — بعد الاعتمادات السابقة
- تطبيق الهوية المعتمدة بالعربية والإنجليزية مع RTL كامل على الصفحة الرئيسية.
- إنشاء طلب وصول يعمل فعلياً مع حالات إرسال ونجاح وفشل واضحة؛ لا نموذج يتظاهر بحفظ الطلب.
- اختبار الصفحة والإجراء الأساسي على الهاتف والحاسوب، وإعداد عنوان ووصف خاصين بالمنتج.
- النشر قرار منفصل؛ لا تعني معاينة الصفحة أنها منشورة أو أن المنتج متاح.

## التوثيق وحدود النطاق
- معرفة العلامة في ملفات موضوعية ضمن `docs/00-company/`، وروابطها بدل تكرار الحقائق.
- كل قرار معتمد يسجل في `docs/04-decisions/`، مع تحديث الحالة وخارطة الطريق في نطاق هذا العمل عند اعتماده؛ تحفظ البدائل المرفوضة.
- لا بناء لميزة الطباعة أو البحث أو التشخيص، ولا أسعار أو حصص نهائية أو دفع أو اختبارات على راوترات، ضمن هذا المسار.
- تستمر دراسات المنتج والتحقق بصورة منفصلة؛ صفحة الهبوط لا تغلقها.

## تفاصيل تقنية عند التنفيذ فقط
- الحفاظ على TanStack Start والصفحة الرئيسية الحالية كنقطة تنفيذ، دون بناء المنصة أو اختيار بنيتها الآن.
- ألوان وظلال موحدة في `src/styles.css` وعناصر التحكم الحالية، مع خط عربي ولاتيني متوافقين مع SSR.
- إذا اعتمد جمع طلبات الوصول داخل الموقع، يتطلب تخزيناً حقيقياً عبر Lovable Cloud وضوابط منع إساءة الاستخدام والخصوصية؛ لا تفعيل له في مرحلة تخطيط الهوية.

## معيار الإتمام
اسم ونبرة وهوية معتمدة، دليل تصميم مترابط، صفحة ثنائية اللغة مع إجراء حقيقي ومختبر، وفصل واضح بين الموجود والقادم؛ مع سلامة الروابط وحدود أحجام ملفات الشركة.
