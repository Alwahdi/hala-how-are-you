# تحسين واجهة الدخول وتجربتها وتفاعلاتها

## النطاق
تحسين تسجيل الدخول وإنشاء الحساب واستعادة كلمة المرور وقسم «طرق الدخول» في الإعدادات، باعتبارها الشاشات المقصودة في سياق الطلب الأخير. لا إعادة تصميم بقية التطبيق، ولا تغيير لقناة WhatsApp أو قواعد الحسابات، ولا نشر.

## ما كشفته المراجعة
- اختيار طريقة الدخول، واختيار الدخول/الحساب الجديد، وزر الإرسال تتنافس بصريًا؛ تظهر عدة أزرار بارزة قبل بدء الكتابة.
- الخلفية النقطية تظهر داخل الحقول وتضعف هدوء النموذج.
- اختيار الهاتف يعرض رقمًا وكلمة مرور وزرًا معطّلًا رغم أن المطلوب رقم ورمز؛ هذا مسار مسدود لا ينبغي عرضه كنموذج جاهز.
- لا يوجد إظهار لكلمة المرور، والاستعادة ما زالت محاطة بخيارات دخول لا تحتاجها.
- قسم طرق الدخول يعرض تغيير البريد مباشرة بدل إظهار الحالة أولًا ثم فتح التعديل عند الطلب.

## التصميم المقترح
### 1. شاشة دخول أهدأ وأوضح
- الحفاظ على هوية Mikro الداكنة والأخضر المعتمد، مع تخفيف الخلفية محليًا وجعل الحقول ذات خلفية مقروءة؛ دون صندوق زخرفي يحيط بالصفحة.
- عنوان يتغير بحسب المهمة: «تسجيل الدخول»، «إنشاء حساب»، «استعادة كلمة المرور».
- اختيار البريد والهاتف بمظهر هادئ وحالة اختيار واحدة واضحة؛ زر التنفيذ وحده هو الأبرز.
- استبدال الصف الثاني من الأزرار برابط سياقي واحد: «ليس لديك حساب؟ إنشاء حساب» أو «لديك حساب؟ تسجيل الدخول».
- وضع «نسيت كلمة المرور؟» قرب حقلها، وفاصل واضح قبل Google في الدخول وإنشاء الحساب فقط.

### 2. تفاعلات النموذج
- إظهار/إخفاء كلمة المرور بأيقونة مسماة، مع إبقاء المدخلات محفوظة عند الخطأ.
- حالات تركيز وانتظار ونجاح وخطأ واضحة، ومنع النقر المتكرر أثناء الطلب؛ رسائل قصيرة قرب النموذج دون كشف وجود حساب.
- عرض نتيجة تأكيد البريد أو طلب الاستعادة بوضوح، مع رجوع مباشر للدخول.
- في استعادة كلمة المرور: توضيح عدم تطابق التأكيد قرب الحقل بدل زر معطّل بلا تفسير، وحالة حفظ مرئية.
- انتقالات خفيفة لا تحرك الحقول عشوائيًا، مع احترام تقليل الحركة.

### 3. الهاتف دون وعد زائف
- إبقاء خيار الهاتف ظاهرًا مع إشارة «غير متاح حاليًا».
- عند اختياره: بيان قصير «الدخول برقم الجوال غير متاح حاليًا» وزر «المتابعة بالبريد»؛ لا طلب رقم أو كلمة مرور ولا زر إرسال رمز يوحي بأنه يعمل.
- لا تنفيذ دخول الرقم والرمز ضمن هذا التحسين؛ عائقه الحالي محفوظ في D-040 وD-041.

### 4. طرق الدخول في الإعدادات
- عرض كل طريقة في صف واضح: الأيقونة، الاسم، الحالة المؤكدة، والإجراء المتاح.
- فتح إضافة/تغيير البريد عند الضغط فقط، مع إلغاء واضح وحالة انتظار التأكيد.
- فصل الخطأ عن النجاح والتحميل عن «غير مرتبط»، وإظهار الهاتف غير المتاح دون زر ربط وهمي.
- عدم عرض إضافة كلمة مرور أو ربط هوية لا تدعمهما الوظائف الحالية.

## مراجعة مبادئ قابلية الاستخدام العشرة
| المبدأ | نتيجة المراجعة والإجراء |
|---|---|
| ظهور الحالة | يحتاج تحسينًا: تحميل مستقل ونتيجة واضحة وحالة تأكيد البريد |
| مطابقة الواقع | يحتاج تحسينًا: حذف نموذج هاتف/كلمة مرور يناقض رقم/رمز |
| التحكم والحرية | يحتاج تحسينًا: رجوع وإلغاء التعديل دون فقد المدخلات عند الفشل |
| الاتساق | يحتاج تحسينًا: اختيار هادئ وزر تنفيذ بارز واحد |
| منع الأخطاء | يحتاج تحسينًا: عدم تطابق كلمة المرور ومنع الإرسال المتكرر |
| التعرف بدل التذكر | يحتاج تحسينًا: عرض طرق الدخول وحالتها قبل التعديل |
| المرونة والكفاءة | مستوفى جزئيًا: المحافظة على التعبئة التلقائية وGoogle واستكمال لوحة المفاتيح |
| الجمال والبساطة | يحتاج تحسينًا: تخفيف الخلفية وحذف صف الخيارات المكرر |
| إصلاح الخطأ | يحتاج تحسينًا: رسالة موضعية وخطوة تالية قابلة للتنفيذ |
| المساعدة | يحتاج تحسينًا: مساعدة قصيرة عند شرط كلمة المرور أو رابط منتهٍ فقط |

الأثر المتوقع هو تقليل الالتباس وخطوات الاختيار؛ لا ادعاء بزيادة التحويل دون قياس. لا تغييرات تسعير أو تكاليف إرسال ضمن النطاق.

## التفاصيل الفنية
- تعديلات العرض في صفحات `/auth` و`/reset-password` وقسم طرق الدخول؛ إعادة استخدام عناصر التصميم والألوان والخطوط الحالية.
- الاحتفاظ بطلبات الدخول والتأكيد والاستعادة الحالية وبقواعد الأمان؛ لا تغييرات على التخزين أو إعدادات خدمة الدخول.
- توثيق اعتماد التحسين ونتائج الفحص في وثائق الشركة وتحديث حالة العمل بعد الموافقة، دون تعديل وثائق معتمدة مسبقًا قبلها.

## التحقق ومعيار القبول
- فحص العربية والإنجليزية عند عرض 360 و934 و1280، وعدم تجاوز النص أو تداخل الأزرار.
- تنفيذ اختيار الطريقة، إنشاء الحساب، الرجوع، إظهار كلمة المرور، فتح/إلغاء تعديل البريد بلوحة المفاتيح واللمس.
- التأكد أن اختيار الهاتف لا يطلب بيانات ولا يرسل طلبًا، والاستعادة لا تعرض Google أو نموذج الدخول العادي.
- فحص أخطاء النموذج وحالات الانتظار دون إرسال رسائل أو تغيير الحساب الحقيقي؛ إرسال الرسائل والربط الفعلي يحتاج نطاق اختبار معتمد منفصلًا.
- تشغيل الاختبارات القائمة المتأثرة، وتسجيل ما تم التحقق منه وما بقي غير متاح؛ لا نشر ولا عمليات على الراوترات.
