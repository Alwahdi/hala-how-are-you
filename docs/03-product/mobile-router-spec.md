# مواصفة عنوان الراوتر والربط المحلي والبعيد للجوال

**الملخص:** [confirmed] طلب المؤسس حقل عنوان يقبل IP محليًا أو DDNS بعيدًا، وترتيب النص الملصوق واستخراج المنفذ وإظهاره مباشرة؛ المصدر: محادثة 2026-11-13.
[assumption] توسيع تصميم الربط البعيد للمراجعة في D-049، بعد تأجيله في الخطة الأصلية؛ لا يثبت الوصول أو يغير ربط الويب.

## المشكلة والهدف
- [assumption] تخفيف مساعدة المهندس المتكررة لصاحب الشبكة PER-001 في P-003 وP-010؛ تعريف الأطراف والمشاكل في [المشاكل](../01-discovery/problems.md).
- [assumption] معيار النجاح: يربط المالك راوتر الاختبار ويختار النظام المتاح دون حساب سحابي، وتظهر نتيجة الفشل مع سبب وخطوة إصلاح.

## رحلة المستخدم
0. [assumption] البداية «الشبكات»؛ اختيار اتصال محفوظ يفتح مساحة الراوتر وفق [مواصفة القائمة](mobile-saved-networks-spec.md). يبقى الأرشيف والقوالب متاحين عند غيابه مع بيان أنها بيانات محفوظة، ولا يبدأ اتصال ناجح أو إصدار لمجرد فتح المساحة.
1. [assumption] يفتح «إضافة شبكة»؛ يوضح أن العنوان المحلي يحتاج الوصول لشبكته وإذن الشبكة المحلية عند طلب النظام، والعنوان البعيد يحتاج مسار وصول فعليًا.
2. [assumption] يختار نتيجة اكتشاف أو يدخل العنوان؛ الاكتشاف مساعد ولا يمنع الإدخال اليدوي.
3. [confirmed] طلب المؤسس جمع الوجهة وبيانات الدخول في بطاقة واحدة؛ المصدر: محادثة 2026-11-13، [D-052](../04-decisions/D-052-mobile-network-hub.md).
   [assumption] داخلها زر الاستكشاف، ثم «عنوان الراوتر» بتلميح «رابط التحكم عن بُعد أو IP» والمنفذ بجواره؛ وأسفلهما اسم المستخدم وكلمة المرور وزر الإظهار وتوضيح أنها بيانات الراوتر، ثم فعل الفحص. تبقى التسميات مستقلة دون اختيار نوع الخدمة في المسار الأساسي.
4. [assumption] يضغط اختبار الاتصال؛ لا يجري تثبيت سكربت أو إنشاء مستخدم أو تغيير إعداد راوتر في اختبار القراءة.
5. [assumption] تظهر هوية الراوتر وإصداره والخدمات والصلاحيات المتاحة؛ يسمي الاتصال ويحفظه باختياره.
6. [assumption] إذا كانت القراءة ممكنة والكتابة مرفوضة، يفتح المحفوظ/القراءة مع تفسير منع الإصدار؛ لا يطلب صلاحيات إدارة شاملة تلقائيًا.
7. [assumption] خطأ الوجهة يبقي بيانات الدخول في ذاكرة النموذج لتصحيح الخطأ؛ تحفظ كما كتبها المستخدم دون تطبيع. تلغى المسودة عند مغادرة الربط للقائمة أو بدء اتصال آخر، ولا تدخل حالة العرض المحفوظة؛ هذا ليس تنفيذ خزنة اعتماد دائمة.

## ترتيب العنوان والمنفذ
- [assumption] عند اللصق أو مغادرة الحقل يزال فراغ الطرفين وhttp/https من النص، ويفصل اسم المضيف عن المنفذ؛ يزال مسار صفحة الويب والاستعلام والجزء المرجعي من وجهة API مع بيان التغيير وإتاحة التراجع.
- [assumption] يحفظ المنفذ المكتوب صراحة حتى لو كان منفذ ويب شائعًا؛ لا تعتمد قيمة URL الافتراضية التي قد تخفيه، ولا يحول إلى منفذ API آخر بصمت.
- [assumption] إذا حمل النص منفذًا مختلفًا عن الحقل يستخدم الملصوق مع رسالة توضح التبديل وإمكان التراجع. حذف http/https لا يحدد تشفير API ولا يحول REST إلى RouterOS API.
- [assumption] تقبل الأرقام العربية للعنوان الرقمي والمنفذ وتحول للأرقام اللاتينية؛ ترفض بيانات المستخدم المضمنة في الرابط والصيغ غير المسموحة والمنفذ غير الصالح برسالة موضعية.
- [assumption] IPv6 مع منفذ يستخدم الأقواس؛ عنوان IPv6 العاري لا يخمن منه منفذ. نطاقات DNS المقبولة والتحقق الفعلي يعتمدان محللًا موثوقًا عند البناء؛ لا يسند حل DNS إلى نجاح تنسيق النص.

| مثال تصميم [assumption] | المضيف بعد الترتيب [assumption] | المنفذ [assumption] |
|---|---|---|
| `http://192.168.88.1/` | `192.168.88.1` | يبقى المنفذ الظاهر |
| `https://router.example.net:8778/webfig/` | `router.example.net` | `8778` |
| `https://router.example.net:443/` | `router.example.net` | يبقى `443` مع تنبيه فحص نوع الخدمة |
| `[2001:db8::1]:8778` | `2001:db8::1` | `8778` |

## الاتصال الفعلي والمساعدة
- [confirmed] طلب المؤسس التعرف التلقائي على طريقة الاتصال بدل اختيار TLS يدويًا؛ المصدر: محادثة 2026-11-13، [D-050](../04-decisions/D-050-novice-owner-interactions.md).
- [assumption] التعرف محاولة محدودة للخدمة على الوجهة والمنفذ المقصودين، لا افتراض من http أو اسم الملف أو المنفذ وحده. تظهر نتيجة الحماية التي أمكن التحقق منها؛ المنفذ المخصص لا يستبدل بصمت.
- [confirmed] المنافذ والبروتوكولات وحدودها في [مرجع API](../06-mikrotik/api-rest.md)؛ راجعت [توثيق MikroTik](https://help.mikrotik.com/docs/spaces/ROS/pages/47579160/API) بتاريخ 2026-11-13. المنفذ المخصص يختبر كما ضبطه المستخدم؛ لا يساوي منفذ Winbox أو الويب تلقائيًا.
- [confirmed] [توثيق IP Cloud](https://help.mikrotik.com/docs/spaces/ROS/pages/97779929/Cloud) يصف DDNS وتحذير اختلاف العنوان وراء NAT؛ راجعت بتاريخ 2026-11-13. حدود المسار في [مرجع الوصول البعيد](../06-mikrotik/remote-access.md)، لا وعد بتجاوز CGNAT من الاسم وحده.
- [assumption] يختبر الوصول ثم هوية الراوتر والخدمة والحماية والمصادقة والصلاحيات؛ لا يعرض «متصل» من صحة العنوان، ولا يفتح خدمات أو جدارًا ناريًا تلقائيًا.
- [assumption] يفضل الاتصال المشفر والتحقق من شهادة الراوتر؛ لا يخفض التشفير بعد فشل شهادة بصمت. الخدمة غير المشفرة توضح أثرها قبل إرسال الاعتماد، والاختيار يعتمد صلاحية الشبكة ومسار الوصول المختبر.
- [confirmed] [توثيق RouterOS الحالي](https://manual.mikrotik.com/docs/developer-guides/api/) يوضح أن API-SSL دون شهادة يعرض تشفير DH مجهولًا لا تقبله عملاء TLS الحالية؛ مراجعة 2026-11-13. لذا لا تكفي محاولة handshake فاشلة لاستنتاج أن الخدمة API غير مشفرة، ويلزم فشل قابل للفهم وخطوة تصحيح بدل ضمان اكتشاف كل راوتر.
- [assumption] المساعدة بجوار الحقل: «وين ألقى العنوان والمنفذ؟» ثم شرح مختصر؛ فشل DNS يختلف عن مهلة الشبكة ورفض الدخول ونقص الصلاحية، وكل نتيجة تقترح خطوة مناسبة.
- [assumption] «أحتاج بيانات الربط أو مساعدة» متاح من البطاقة والنتائج الفاشلة؛ يوضح العنوان ومنفذ API والحساب المخول، ويقدم نص طلب عام يستطيع المالك نسخه للمهندس دون أسرار. لا إرسال آلي أو ادعاء أن الاستكشاف يستخرج كلمة المرور أو يفتح خدمة، والعودة تبقي المسودة المؤقتة حتى الخروج من الربط.

## الاستكشاف المحلي
- [assumption] فعل ظاهر داخل بطاقة الربط، يبدأ بإرادة المستخدم أثناء وصوله للشبكة المحلية؛ لا مسح تلقائي مستمر أو بحث في الإنترنت. يمكن الإدخال اليدوي من البداية وعند أي فشل.
- [assumption] تظهر حالة بحث قابلة للإلغاء، ثم قائمة أسماء وعناوين أو حالة فشل. اختيار نتيجة يملأ العنوان ويحافظ على المنفذ المقصود؛ لا يثبت وصول API أو مصادقة أو صلاحية بمجرد إعلان الجهاز عن نفسه.
- [assumption] تميز النتائج بين عدم ظهور أجهزة ورفض الإذن وعدم دعم الاكتشاف وغياب المسار المحلي عندما يمكن إثبات السبب؛ لا تستنتج «إذن مرفوض» من مهلة عامة. عدم النتائج لا يثبت غياب الراوتر أو تعطله.
- [assumption] الإلغاء أو مغادرة البحث يلغي المحاولة ويتجاهل ردها المتأخر. تغير الشبكة أثناء الفحص يلغي ربط النتائج بسياق سابق؛ المحاكاة تختبر الإلغاء والمغادرة فقط، ومراقبة شبكة الهاتف لم تنفذ.
- [assumption] يعرض إرشاد الإذن وإعادة المحاولة دون زر يدعي تغيير إعدادات الهاتف من تلقائه. يحتاج المنفذ المخصص ووجهة VPN والوصول المحلي بلا إنترنت واختلاف الشبكات اختبارًا فعليًا.
- [confirmed] [توثيق MikroTik لاكتشاف الجيران](https://manual.mikrotik.com/docs/system-information-and-utilities/neighbor-discovery/) يحدد MNDP/CDP/LLDP داخل نطاق Layer 2 وإمكان تعطيل الإعلان على الواجهات؛ مراجعة 2026-11-13. استنتاجنا: هذا مساعد لا بديل ضمانًا لفحص الخدمة، ولا إثبات أن تطبيق الهاتف يستطيع تنفيذ كل هذه البروتوكولات.
- [confirmed] [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) يوضح إذن الشبكة المحلية، ومتطلب entitlement لحركة multicast/broadcast في iOS، وأن محاكي النظام لا يختبر هذه الخصوصية؛ مراجعة 2026-11-13. اختيار أسلوب الاكتشاف ومتطلباته ينتظر مختبر هاتف فعلي؛ لا وعد باكتشاف كل راوتر.
- [confirmed] نتائج العرض مصطنعة ومعلّمة خارج الهاتف؛ لا طلب إذن نظام أو مسح LAN فعلي في التصور.

## مساحة الراوتر والخروج
- [assumption] تبويبات العمل داخل مساحة واحدة؛ باقاتها ودفعاتها ومسودتها وإعدادات طباعتها مرتبطة بهوية ذلك الراوتر، ولا ينقل تغيير الوجهة اختيار باقة أو عملية غير مكتملة.
- [assumption] زر «الشبكات» يعيد إلى [قائمة الاتصالات](mobile-saved-networks-spec.md)؛ الخروج من المساحة لا يطفئ الراوتر، ولا يحذف حساباته أو يفترض تسجيل خروج سحابي.
- [assumption] أثناء الإصدار يعرض خيار البقاء أو الإيقاف المنظم وحفظ التقدم والخروج؛ ينتظر انتهاء العملية الجارية وتسوية النتيجة قبل إتاحة تغيير الوجهة. فشل التسوية يبقيها بانتظار التحقق، ولا يعد باستمرار الإصدار في خلفية الهاتف.
- [assumption] فتح المساحة لاحقًا يقدم الدفعة غير المكتملة؛ حالة الحفظ الدائم لا تثبت الاتصال أو نجاح كتابة، وتفاصيل الحفظ في [مواصفة الأرشيف](mobile-archive-spec.md).
- [confirmed] المحاكاة تحفظ حالات الراوترين في ذاكرة العرض فقط؛ ليست تنفيذًا للحفظ بعد إغلاق التطبيق أو ضمانًا لتسوية عملية RouterOS جارية.

## الحالات
| الحالة | وش يشوف المستخدم [assumption] |
|---|---|
| طبيعي | هوية الراوتر و«متصل داخل الشبكة» ووقت آخر قراءة |
| فاضي | إضافة أول راوتر؛ مثال للعنوان دون بيانات حساب جاهزة |
| تحميل | اختبار اتصال جارٍ مع إمكانية الإلغاء؛ لا نجاح قبل الرد |
| الإنترنت مقطوع والراوتر متصل | العمل المحلي متاح، دون تحذير يعطل المهمة |
| إذن الشبكة مرفوض | سبب موضعي ورابط إرشاد لإذن النظام وإعادة محاولة |
| بيانات دخول أو صلاحية مرفوضة | فصل خطأ المصادقة عن نقص صلاحية القراءة/الكتابة |
| الراوتر غير متصل | المحفوظ بتوقيته وإعادة محاولة؛ لا يعرض قائمة فاشلة كصفر كروت |
| خدمة غير مثبتة | User Manager غير متاح بدليل فحص، لا باستنتاج من قائمة فارغة |

## الصلاحيات
- [assumption] مالك الهاتف المخول يختار حساب الراوتر؛ التفويض الحقيقي بصلاحيات ذلك الحساب، لا بزر اختيار دور محلي.
- [assumption] الاختبار الأول قراءة؛ لا تمكين API أو تغيير شهادة أو كلمة مرور أو سياسات تلقائيًا.
- [assumption] الاحتفاظ ببيانات الاتصال يحتاج تصميم خزنة محلية ضمن تجربة التنفيذ؛ لا تسجيل الأسرار في السجلات أو تضمينها في ملفات الوثائق.

## اللغة والاتجاه
- [assumption] عربي/إنجليزي وRTL/LTR؛ عنوان IP والمنفذ وأسماء الأنظمة باتجاه LTR، مع منع لوحة المفاتيح من تغطية فعل الإرسال.

## شروط القبول
- [ ] [assumption] الربط والقراءة يعملان في مختبر كل نظام تشغيل هاتف وإصدار راوتر في مصفوفة التوافق المعتمدة.
- [ ] [assumption] إلغاء الاختبار لا يحفظ بيانات اتصال غير مؤكدة أو يغير الراوتر.
- [ ] [assumption] تغيير الراوتر يعيد تحميل الباقات ولا ينقل اختيار باقة من راوتر سابق.
- [ ] [assumption] الخروج والعودة يحفظان مسودة كل راوتر دون خلطها، والخروج أثناء الكتابة ينتظر تسوية النتيجة قبل تبديل الوجهة.
- [ ] [assumption] رفض الإذن أو نقص الصلاحية أو المهلة تعطي نتائج مختلفة قابلة للإصلاح.
- [ ] [assumption] مع تعطيل الإنترنت واستمرار الوصول المحلي، تظل المهمة المحلية متاحة.
- [ ] [assumption] لصق رابط بمنفذ ومسار يفصل القيم دون فقد المنفذ الصريح؛ تحرير المنفذ والتراجع والتحقق من IPv4/IPv6 وحروف DNS يختبران.
- [ ] [assumption] DDNS ذو مسار صالح يعمل في المختبر؛ انعدام مسار الوصول لا يظهر كنجاح أو يستدعي تغييرًا تلقائيًا للراوتر.
- [ ] [assumption] لا اختيار تقني للتشفير في البداية؛ اختبار TLS بشهادة صحيحة/غير صالحة وخدمة غير مشفرة ومنفذ مخصص وخدمة غير مدعومة يثبت دقة التعرف وعدم التسريب أو التخفيض الصامت.
- [ ] [assumption] بطاقة واحدة واضحة مع لوحة المفاتيح وخط النظام الموسع، والاستكشاف الفعلي ورفض إذنه وإلغاؤه وتغير الشبكة واختيار نتيجة مثبتة الهوية تختبر على iPhone وAndroid.

## خارج النطاق
- [assumption] إنشاء الأنفاق أو خوادم تمرير جديدة، إعداد الراوتر من الصفر، منح حسابات مهندس عبر السحابة، وإصلاح إعدادات الراوتر تلقائيًا. الوصول المباشر البعيد صار ضمن مراجعة التصميم الحالية في D-049، ولم يعتمد تنفيذه بعد.
