# مواصفة إصدار الكروت محليًا للجوال

**الملخص:** [assumption] إصدار واضح قابل لتسوية الانقطاع، من اختيار الباقة إلى الحساب المؤكد، قبل إتاحة الطباعة؛ مسودة للاعتماد.

## المشكلة والهدف
- [assumption] خدمة PER-001 وتقليل التعديلات والمساعدة اليومية في [P-003 وP-010](../01-discovery/problems.md)؛ قواعد الأعمال السابقة في [تحليل الإصدار](../01-discovery/voucher-issuance.md).
- [assumption] النجاح: حسابات بالعدد والوجهة والحقوق الصحيحة، وفصل المعلق عن الفاشل؛ لا تعويض نقص الدليل بنجاح عام.

## رحلة المستخدم
1. [assumption] من فعل «إضافة كروت» يختار كرتًا واحدًا أو دفعة، ثم النظام والباقة على الراوتر المحدد؛ يظهر ملخص مستقل لحقوقها المتوفرة والقيم غير المعروفة.
2. [assumption] الكرت الواحد يبدأ بتوليد الرقم، مع خيار مسمى «أكتب الرقم بنفسي»؛ الدفعة تعرض العدد. النمط أساسي، والبادئة والوسط واللاحقة والطول ونوع المحارف خيارات إضافية عند الحاجة؛ تحفظ الأصفار البادئة ولا يثقل المسار السريع بكل إعداد.
3. [assumption] الرقم فقط أو كلمة مرور مطابقة أو مختلفة؛ تبقى الأمثلة معلّمة كتوضيح لا حسابات صدرت. وسم الدفعة/نقطة البيع اختياري.
4. [assumption] في Hotspot يراجع المالك حدود الحساب الصريحة؛ لا تستخدم أغلبية كروت قديمة لتعويض حدود غير معروفة.
5. [assumption] المراجعة تثبت الراوتر والنظام والباقة وكل الحقوق والعدد والنمط؛ زر واضح «تأكيد إصدار … كرتًا»، مع تعديل الخطوات قبل التنفيذ.
6. [assumption] تحفظ هوية الطلب وتقدمه قبل الكتابة؛ لا يكرر الضغط طلبًا جديدًا. يكتب المعالج وفق حدود يحددها اختبار الحمل لاحقًا.
7. [assumption] يتأكد وجود الحساب وإسناد الباقة والحدود؛ فشل إسناد الباقة لا يصبح حسابًا جاهزًا للطباعة.
8. [assumption] نتيجة كرت واحد تعرض رقمه والباقة والراوتر ومعرف الدفعة، وتفتح تسليم ذلك الكرت مباشرة. نتيجة الدفعة تفتح معاينة الكروت المؤكدة؛ القالب الجاهز لا يفرض المرور بالمحرر. عند التوقف يظهر الجزء المؤكد وخيار تسوية الباقي.
9. [assumption] التسليم يعرض بيانات الإصدار المخولة من [الأرشيف](mobile-archive-spec.md)، مع فعل نسخ أو مشاركة مراجعة لهذا الكرت، لا تفاصيل استهلاكه بدل بيانات دخوله. الأسرار غير المتاحة أو المبطلة لا تستعاد من التخمين، وفتح المشاركة ليس إثبات تسليم.

## الحالات والاستكمال
| الحالة | وش يشوف المستخدم [assumption] |
|---|---|
| لا باقات أو فشل قراءتها | يفرق بين خلو حقيقي وفشل، مع إعادة محاولة؛ لا يصدر على باقة مفترضة |
| مسودة | محفوظة على الجهاز؛ الرجوع لا يزيل المدخلات ولا يكتب للراوتر |
| إصدار جارٍ | المطلوب والمؤكد والفاشل والمعلق والذي لم يبدأ؛ دون مدة إنجاز مختلقة |
| إيقاف اختياري | توقف منظم بعد تسوية الجاري؛ الاتصال لا يعرض كمنقطع بسبب الإيقاف |
| انقطاع قبل الإرسال | الجزء غير المرسل لم يبدأ؛ لا ينفذ تلقائيًا عند عودة الشبكة |
| فقد رد بعد الكتابة | «بانتظار التحقق»؛ يقرأ النتيجة ويراجع ملكية الطلب قبل أي إعادة |
| إغلاق التطبيق أو إعادة تشغيل الهاتف | استرجاع سجل الطلب، ثم تحقق من الراوتر؛ الذاكرة وحدها لا تكفي |
| اسم موجود مسبقًا | تعارض ظاهر؛ لا استبدال الحساب أو تغيير كلمة مروره |
| رقم يدوي ظهر بعد المراجعة وقبل التنفيذ | تعارض جديد دون استبداله أو توليد رقم آخر بصمت؛ يراجع المستخدم الرقم |
| جزء ناجح وجزء فاشل | طباعة المؤكد فقط وتسوية المتبقي؛ لا وصف الجميع بالمكتمل |
| موارد الراوتر لا تسمح | سبب توقف مؤقت وحفظ تقدم؛ حدود الموارد تثبت بالقياس |

## الصلاحيات
- [assumption] لا إصدار إلا على راوتر وحساب مخولين بالكتابة؛ تغيير الوجهة أو الحقوق بعد التأكيد يعيد المراجعة ولا يعدل طلبًا جارياً.
- [assumption] إلغاء الباقي لا يحذف حسابات صدرت؛ حذف حساب موجود عمل آخر يحتاج تأكيدًا ونطاقًا معتمدًا.
- [assumption] أسرار الإصدار الجديدة تحفظ في خزنة التطبيق ضمن [مواصفة الأرشيف](mobile-archive-spec.md)، دون رفع سحابي إجباري.

## اللغة والاتجاه
- [assumption] عربي/إنجليزي، أرقام لاتينية ورموز LTR؛ أسماء الحالات نصية والأخطاء قرب الحقل ولا تعتمد على اللون.

## شروط القبول
- [ ] [assumption] دورة Hotspot وUser Manager على النسختين المتاحتين في المختبر، مع تطابق العدد والحقوق.
- [ ] [assumption] تكرار الضغط وإعادة فتح التطبيق وفقد الرد لا يكرر الحسابات أو يستبدل موجودًا.
- [ ] [assumption] فشل إسناد الباقة وتغير تعريفها خارج التطبيق يكشفان قبل إعلان الجاهزية.
- [ ] [assumption] الاستكمال يعيد الطلب نفسه، ويتحقق من المعلق قبل تسليم جديد؛ لا تعتمد هوية الدفعة على تعليق قابل للتغير وحده.
- [ ] [assumption] يتم اختبار حجم الدفعة تدريجيًا وفق الخطة، وتبقى أرقام الأهداف غير ضمان للأداء.

## خارج النطاق
- [assumption] توليد حسابات في غياب اتصال بالراوتر، تحرير باقات شامل، استبدال حسابات متعارضة، حذف تلقائي لدفعة، أو إصدار متزامن من أجهزة متعددة.
