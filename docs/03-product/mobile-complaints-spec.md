# مواصفة شكوى الكرت وقراءات الدليل

**الملخص:** [confirmed] طلب المؤسس تسجيل شكوى للكرت وتجميع معلومات تفيد في متابعة الاستخدام والأجهزة وموضع الاتصال عند توفره؛ المصدر: محادثة 2026-11-13.
[assumption] الشكوى سجل متابعة محلي مخول، وليست حكمًا على الزبون أو تكليفًا بمراقبة كل الشبكة.

## المشكلة والهدف
- [assumption] تخدم PER-001 في الشكاوى المتكررة المرتبطة بـP-003؛ [المشاكل](../01-discovery/problems.md) و[دليل الاحتياج](../01-discovery/network-owner-workflows.md).
- [assumption] النجاح: يحتفظ المالك بوصف المشكلة وقراءة وقتها، ويضيف دليلًا محدودًا لاحقًا ثم يجد الشكوى ويغلقها، دون فقد الدليل عند تجديد الكرت.

## رحلة المستخدم
1. [assumption] من نتيجة الكرت يضغط «تسجيل شكوى»؛ يحمل الراوتر والنظام ومعرف الكرت، ويختار نوعًا مفهومًا مثل الاستهلاك أو الدخول أو التقطع، مع ملاحظة اختيارية.
2. [assumption] يحفظ تسجيل الشكوى قراءة ذات مصدر ووقت رصد ووقت حفظ مستقلين؛ الحالة السابقة تبقى مؤرخة إذا كان الراوتر غائبًا.
3. [assumption] تبقى الشكوى مفتوحة حتى إغلاقها بفعل صريح؛ الوصول من «المزيد ← الشكاوى» أو من الكرت المرتبط. لا تغيير حساب أو تعويض بسبب التسجيل وحده.
4. [assumption] متابعة قراءات إضافية اختيارية ومحددة بهذا الكرت؛ يوضح متى تعمل ومتى تتوقف، مع فعل لإيقافها. لا تعد الواجهة بتسجيل أثناء إغلاق التطبيق قبل اختبار قيود الجهاز واعتماد النطاق.
5. [assumption] تضاف العينات بتاريخها دون استبدال التاريخ القديم؛ تجديد الكرت لا يصفر أدلة الشكوى السابقة ولا يخلط دورة الرصيد الجديدة بالسابقة.
6. [assumption] الإغلاق يحفظ السجل ويوقف المتابعة؛ حذف أو تصدير أو مزامنة الدليل يحتاج سياسة احتفاظ وصلاحيات معتمدة قبل البناء.

## ما يمكن أن يكون دليلًا
- [assumption] هوية الراوتر والنظام والكرت، الباقة والحدود، التحميل والرفع ووقت الاستخدام وحالة الوصول، وعينات جلسات متاحة المصدر والتوقيت.
- [assumption] MAC عنوان جهاز مرصود؛ لا يثبت هوية إنسان، وقد يتغير أو يعاد استخدامه. لا ينشأ عنوان جهاز من عدم وجود جلسة أو سجل.
- [assumption] اسم منفذ ether أو نقطة البث لا يستنتج من MAC أو إجمالي الاستهلاك؛ لا يظهر إلا من قراءة موثوقة تربط الجهاز بمصدر الاتصال وقتها، وإلا «غير متاح».
- [assumption] ظهور أكثر من MAC يحتاج ترتيبًا زمنيًا وتفسير تزامن الجلسات وقواعد المشاركة؛ لا يساوي وحده إساءة استخدام أو سرقة كرت.
- [confirmed] حدود مايكروتيك والمحاسبة وعدم مساواة الجلسة بهوية جهاز منزلي محفوظة في [أدلة البيانات](../01-discovery/network-owner-data-evidence.md)؛ لا تفترض هذه المواصفة اكتشاف نشاط التطبيقات.

## الحالات والخصوصية
| الحالة | ما يراه المستخدم [assumption] |
|---|---|
| لا سجل جلسة | الدليل غير متاح؛ لا MAC أو منفذ مختلق |
| انقطاع | تتوقف القراءة؛ آخر دليل محفوظ بتوقيته، لا عينات صفرية زائفة |
| إذن أو صلاحية مفقودة | يفسر ما لا يمكن جمعه؛ الشكوى لا تضيف صلاحيات |
| غادر شاشة المتابعة | السجل محفوظ، وحالة المتابعة متوقفة أو وفق النطاق المختبر صراحة |
| تغير حساب الكرت خارجيًا | حدث منفصل أو حالة غير محسومة؛ لا دمج خفي لدورات مختلفة |
| أرسل ردًا للزبون | لا تنقل الملاحظة الخاصة أو كل MAC تلقائيًا؛ [سياسة الرد](mobile-voucher-report-spec.md) |

- [assumption] لا رفع جماعي لعناوين أجهزة الزبائن إلى ملف حساب المالك السحابي، ولا تتبع خارج الشبكة أو استدلال هوية من بصمة جهاز.
- [assumption] الحفظ المحلي محمي ويشمل فتحًا مخولًا وتصديرًا مقصودًا؛ مدة الاحتفاظ والحذف والإذن قبل أي مشاركة خارجية تحتاج اعتمادًا.
- [assumption] جمع الدليل خفيف ومحدود بالمهمة؛ لا قراءة تاريخ User Manager كله أو قراءات متراكبة، وتختبر وتيرة مقبولة في المختبر قبل تشغيل متكرر.

## اللغة وشروط القبول
- [assumption] حالات «مفتوحة»، «مغلقة»، «متوقفة المتابعة»، و«قراءة سابقة» نصوص واضحة بالعربية والإنجليزية؛ لا تعتمد الحالة على اللون.
- [ ] [assumption] رقم متكرر بين راوترين أو نظامين ينتج سياقين منفصلين للشكوى، ولا ينقل الدليل بينهما.
- [ ] [assumption] غياب جلسة أو منفذ لا يولد دليلًا افتراضيًا، والعينات توضح وقت الرصد لا وقت فتح الشاشة فقط.
- [ ] [assumption] التجديد والإغلاق والعودة لا يمحون قراءة سابقة، وإيقاف المتابعة يمنع جمعًا لاحقًا حتى تفعيلها مجددًا.
- [ ] [assumption] توجد سياسة حفظ وحذف معتمدة واختبار صلاحيات قبل تخزين بيانات حقيقية.

## خارج النطاق
- [assumption] اعتراض محتوى المستخدم، التعرف على الأشخاص، اتهام الزبون تلقائيًا، مراقبة خفية أو خدمة خلفية دائمة، وتعويض أو تجديد غير مؤكد.
