# مواصفة رد الزبون ومشاركة تقرير الكرت

**الملخص:** [confirmed] طلب المؤسس إرسال نتيجة فحص الكرت كصورة أو نص، واختيار WhatsApp أو رسالة نصية؛ المصدر: محادثة 2026-11-13.
[assumption] المالك يراجع التقرير ومحتواه ثم يختار المستلم في وسيلة المشاركة؛ مسودة تجربة قبل بناء التصدير أو الربط بالنظام.

## المشكلة والهدف
- [assumption] يخدم PER-001 في شرح شكوى الاستهلاك ضمن P-003؛ [تعريف المشاكل](../01-discovery/problems.md) و[حدود الاستنتاج](../01-discovery/voucher-support.md).
- [assumption] النجاح: يجهز ردًا يخص الكرت الصحيح وقراءته، بلا كلمة مرور أو ملاحظة خاصة، ويميز تجهيز الرد عن إرساله وتسليمه.

## رحلة المستخدم
1. [assumption] نتيجة الفحص تتيح «إرسال تقرير للزبون»، دون إعادة إدخال الكرت أو تغيير الراوتر.
2. [assumption] يراجع صورة مقروءة أو نصًا؛ يحمل التقرير هوية الكرت والنظام وملخص الباقة والحجم المستخدم والمتبقي والتحميل والرفع ووقت الاتصال والصلاحية كما تتوفر، ومصدر القراءة وعمرها.
3. [assumption] الغائب يعرض «غير متاح»؛ التقرير ليس مكانًا لاختراع سبب استهلاك أو تاريخ جلسات مفقود.
4. [assumption] كلمة المرور وبيانات حساب الراوتر ورقم الحساب الخاص وملاحظات الشكوى الداخلية مستبعدة؛ تضمين MAC أو التفاصيل الحساسة اختيار مستقل معلن الغرض، وليس افتراضيًا.
5. [assumption] يختار WhatsApp أو SMS أو مشاركة النظام. مسار SMS نصي؛ عند اختياره من صيغة صورة يحول إلى النص مع بيان التغيير، وتبقى مشاركة الصورة بوسيلة تدعمها اختيارًا آخر.
6. [assumption] يفتح التطبيق الفعلي وسيلة المشاركة بفعل صريح، ويختار المستخدم الزبون ويرسل بنفسه. لا إرسال تلقائي أو استنتاج نجاح التسليم من فتح النافذة.

## الحالات
| الحالة | ما يراه المستخدم [assumption] |
|---|---|
| الراوتر غير متصل | تقرير «قراءة سابقة» مؤرخ؛ لا عنوان يوحي بأن حالته الآن مؤكدة |
| لا بيانات كافية | لا تقرير استهلاك كامل زائف؛ يوضح الناقص |
| صورة تعذر تجهيزها | يبقى النص وبيانات الفحص؛ إعادة محاولة أو مشاركة نص |
| التطبيق المقصود غير متوفر | اختيار مشاركة نظام أو نص؛ لا إجبار على تثبيت خدمة |
| ألغى المستخدم المشاركة | التقرير باقٍ؛ لا «تم الإرسال» |
| بيانات تغيرت أثناء التجهيز | نسخة معلومة التوقيت؛ لا مزج قراءتين في تقرير واحد |

## اللغة والصلاحيات
- [assumption] عربي/إنجليزي وRTL/LTR؛ الصورة والنص يحفظان الأصفار البادئة ويمنعان انعكاس الأرقام، ويختبران على عرض هاتف الزبون.
- [assumption] إعداد التقرير قراءة/تصدير مخول فقط؛ لا تجديد أو إصدار حسابات. الملف المؤقت لا يصبح رابطًا عامًا أو يرفع لخادم تلقائيًا.
- [assumption] اختيار مستلم تقرير لا يمنح ملكية الحساب لذلك المستلم؛ مشاركة تفاصيل أجهزة أشخاص آخرين تحتاج بيانًا واختيارًا مناسبًا.

## شروط القبول
- [ ] [assumption] الصورة والنص يتفقان على الكرت والراوتر والنظام والتوقيت والحدود، ويتعاملان مع القيم غير المتاحة.
- [ ] [assumption] بيانات الدخول وملاحظات الشكوى الداخلية لا تتسرب إلى أي صيغة أو إلى مشاركة محذوفة اختياريًا.
- [ ] [assumption] لا يدعي مسار SMS النصي نقل صورة؛ ولا تعني المشاركة تسليمًا مؤكدًا.
- [ ] [assumption] فشل إنشاء الصورة أو إلغاء المشاركة لا يغير حساب الكرت أو حالة الشكوى.

## خارج النطاق
- [assumption] الإرسال الآلي، حملات الرسائل، ضمان تثبيت WhatsApp أو إيصال الرسالة أو إرسال MMS من كل جهاز، واستنتاج بيانات لم يجمعها الراوتر.
