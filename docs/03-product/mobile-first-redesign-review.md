# مراجعة إعادة التصميم بأولوية الهاتف

**الملخص:** [confirmed] طلب المؤسس إعادة تصميم الشاشات والرحلات بتاريخ 2026-11-12، مع أولوية الهاتف ومراجعة NN/g.
[confirmed] هذه مراجعة وخطة قبل التنفيذ؛ لا شهادة بأن جميع منشورات NN/g مطبقة، ولا اختبار مستخدم حقيقي.

## المراجع المقروءة
- [confirmed] قُرئ مقال [المبادئ العشرة](https://www.nngroup.com/articles/ten-usability-heuristics/)؛ هي قواعد تقييم عامة وليست قائمة مواصفات ملزمة لكل تطبيق.
- [confirmed] قُرئت توصيات [النماذج: التنظيم والشفافية والوضوح والدعم](https://www.nngroup.com/articles/4-principles-reduce-cognitive-load/)، و[أهداف اللمس](https://www.nngroup.com/articles/touch-target-size/)، و[الإظهار التدريجي](https://www.nngroup.com/articles/progressive-disclosure/).
- [confirmed] مرجع اللمس يناقش الحجم الفيزيائي والمسافة، لا يساوي رقمًا ثابتًا من CSS pixels؛ يختبر التطبيق فعليًا ولا يُنسب حد 44px للمقال.
- [confirmed] لم تقرأ كل مقالات الموقع أو تقاريره المدفوعة؛ مبادئ المشروع الدائمة مصدرها القرار المرتبط، ولا تنسخ هنا.

## الدليل الحالي
- [confirmed] فُتحت شاشات الإعداد ولوحة الشبكة بأقسامها والإعدادات والصحة والتنبيهات بجلسة فعلية عند 390×844؛ لا تجاوز عرض أو أخطاء JavaScript في هذه الزيارات.
- [confirmed] فتح /auth بجلسة مصادق عليها انتقل للوحة؛ لا يعد ذلك فحصًا لتسجيل دخول ناجح جديد. مراجعة الدخول السابقة محفوظة في D-042.
- [confirmed] الصفحة الحالية /routers تعيد التوجيه إلى قسم «المزيد»، و/ welcome يعيد إلى الإعداد؛ الدليل: المتصفح وملفات التوجيه.
- [confirmed] فُتحت نافذة باقة وتأكيد إعادة الربط وأُغلقتا بـ Escape عند 360px بالعربية، مع منع كل طلبات غير GET/HEAD/OPTIONS محليًا؛ لم يُقدّم نموذج أو يُضغط تأكيد.
- [confirmed] الزيارة الأولى لـ «المزيد» و«التنبيهات» سبقت اكتشاف الآثار التلقائية: الأولى قد تطلب فحص وصول مباشر والثانية تحدّث حالة المقروء؛ لذلك لا توصف تلك الزيارات بأنها خالية من الآثار. لم يتحقق وقوع فحص راوتر أو تغيير حالة مقروء فعليًا، ومنعت الطلبات في الفحص اللاحق.
- [confirmed] لم تُرسل أوامر حذف أو تجديد أو إعادة تشغيل أو إصدار بيانات ربط، ولم ينشر التطبيق. لا إثبات لتعدد الراوترات أو آلاف الكروت في جلسة المراجعة.

## نتائج تتطلب التصميم أو التصحيح
| المجال | النتيجة |
|---|---|
| الحساب والإعدادات | [confirmed] شكل الكروت وثلاث معاينات يسبق طرق الدخول ويستهلك أول شاشة الهاتف؛ `settings.tsx:76–132`. [assumption] فصل الحساب عن إعدادات الشبكة يحسن العثور على المهمة. |
| الإدارة | [confirmed] إدارة الراوترات أسفل روابط الحساب والخروج في «المزيد»؛ `dashboard.tsx:172–180`. [assumption] وجهة مسماة أوضح من تجميعها تحت «المزيد». |
| الإعداد الأولي | [confirmed] أخطاء قراءة الملف والعدد لا تعالج قبل اختيار مسار البداية؛ `onboarding.tsx:54–65`. [assumption] يلزم انتظار/فشل/إعادة محاولة بدل إعادة تقديم نموذج حساب. |
| الباقات | [confirmed] البحث والباقات المطوية موجودان بعد الإصلاح السابق؛ لا إعادة تسجيلهما كعيب. [assumption] العرض الموسّع بعمودين على الهاتف يحتاج ملخصًا أو عمودًا واحدًا؛ `cards-tab.tsx:200`. |
| اللمس | [confirmed] بعض المساعدة والتحديد تستخدم 36–40 CSS px؛ `cards-tab.tsx:195–197,224–226`. [assumption] تكبير منطقة اللمس مع فصل الأهداف يحسن الاستخدام. |
| السجل | [confirmed] كل مهمة غير reboot تسمى إزالة كروت؛ `alerts.tsx:45–46`. [confirmed] أخطاء القراءة لا تُرفع رغم وجود متغير jobsError؛ `alerts.tsx:38–39`. يحتاج تصحيحًا قبل وصف السجل بأنه موثوق. |
| الرجوع | [confirmed] رجوع التنبيهات يفتح الرئيسية بدل القسم السابق؛ `alerts.tsx:52`. [assumption] الرجوع السياقي يقلل فقد مكان العمل. |
| كثافة العرض | [confirmed] الخلفية النقطية واضحة عبر الشاشات التشغيلية. [assumption] أسطح مقروءة وخلفية أهدأ وتسلسل واحد للمعلومات أفضل من كروت زخرفية متداخلة. |

## ما نحافظ عليه
- [confirmed] لا نلغي فصل النظامين أو هوية الراوتر/النظام/الباقة، أو البحث والتحديد والصفحات وتفاصيل الاستهلاك والإجراءات الحالية.
- [confirmed] لا نعيد ادعاء أخطاء الحداثة والحفظ التي أصلحها D-038؛ يعاد التحقق منها عند تغيير العرض.
- [confirmed] حدود الهاتف وقناة التحقق في D-040/D-041؛ التصميم لا يفعّلها. إصدار الكروت والطباعة وإدارة فريق بصلاحيات جديدة ليست وظائف مكتملة ولا تدخل تلقائيًا.

## اتجاه مقترح
- [assumption] تنقل الهاتف: الرئيسية، الكروت، الراوترات، الحساب؛ النشطون من الرئيسية، والباقات من الكروت، مع بقاء وصول مباشر واضح لهما.
- [assumption] الحساب يعرض الهوية وطرق الدخول واللغة والخروج؛ إعدادات الشبكة تجمع شكل الكروت والتنبيهات والصيانة وبيانات الشبكة دون إخفاء الحفظ.
- [assumption] الصحة والسجل وجهتان مسماتان من الرئيسية والراوترات؛ جميع الروابط الحالية تبقى قابلة للفتح.
- [assumption] لوحة الحاسوب تعرض مقارنة أكثر كثافة عبر عمود تنقل وجداول، لا نسخة هاتف ممدودة.

## حدود الاعتماد التالي
- [confirmed] يلزم اعتماد خطة التنفيذ قبل تغيير التطبيق أو الوثائق approved. النتائج التفصيلية قبل/بعد تسجل هنا دون تعديل الدليل التاريخي السابق.
- [confirmed] اختبار الفحوص والمهام والحفظ الحقيقي يحتاج نطاق حساب وراوتر اختبار معتمد؛ المراجعة البصرية تستخدم اعتراض الكتابات والفحوص التلقائية.
- [assumption] نجاح المراجعة لا يثبت «أفضل تجربة» دون تجربة أشخاص من الجمهور وقياس المهام؛ يقدّم تصميمًا معللًا ومعايير قبول قابلة للفحص.
