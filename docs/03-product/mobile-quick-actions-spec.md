# مواصفة الإجراءات السريعة للكروت والجلسات

**الملخص:** [confirmed] طلب المؤسس إكمال الإجراءات السريعة للكروت والمتصلين مع نتائج مفهومة؛ المصدر: محادثة 2026-11-13.
[assumption] كل إجراء ثابت الهدف وموضح الأثر، ثم تأكيد وقراءة نتيجة. المسودة لا تشغل أوامر راوتر حقيقية.

## المشكلة والهدف
- [assumption] يخدم PER-001 في الدعم اليومي وتقليل P-003 وP-010؛ [المشاكل](../01-discovery/problems.md).
- [assumption] النجاح: يختار المالك إجراءً للعنصر الصحيح، ويفهم الفرق بين فصل اتصال ومنع دخول وتجديد رصيد، ولا يظن طلبًا معلقًا ناجحًا.

## نقاط الوصول
- [assumption] صف الكرت يحمل «تجديد» و«إجراءات» بأهداف لمس واضحة؛ جسم التفاصيل والأزرار عناصر مستقلة، لا أزرار متداخلة أو اعتماد على ضغطة مطولة خفية.
- [assumption] إجراءات الكرت: تفاصيله، [تجديده](mobile-voucher-renewal-spec.md)، إيقاف/إتاحة الدخول، فصل جلساته، [رد الزبون](mobile-voucher-report-spec.md)، و[شكوى](mobile-complaints-spec.md).
- [assumption] صف الجلسة يحمل «فحص الكرت» و«فصل»؛ التفاصيل توضح معرف الجلسة ومصدر الحساب والخدمة ووقت القراءة، دون خلط جلسة واحدة مع كل جلسات الكرت.
- [assumption] قد تكون الخدمة Hotspot ومصدر الحساب User Manager؛ لا يبدل الإجراء مصدر الكرت بسبب خدمة الوصول.

## معاني الأفعال
| الإجراء | الأثر الذي يراجع قبل التنفيذ [assumption] |
|---|---|
| إيقاف دخول جديد | منع مصادقة لاحقة بحسب الخدمة؛ لا يدعي فصل جلسة قائمة أو حذف الرصيد |
| إتاحة الدخول | إزالة قيد الإيقاف؛ لا تعيد رصيدًا أو وقتًا انتهى |
| فصل جلسة | إنهاء الاتصال المحدد فقط؛ يمكن إعادة الدخول بكرت صالح |
| فصل جلسات الكرت | يوضح الجلسات المستهدفة الحالية؛ لا يختار جميع الشبكة |
| تجديد | الحقوق والباقة حسب [مواصفته](mobile-voucher-renewal-spec.md)؛ ليس فصل جلسة أو استبدال كلمة مرور |

## دورة الطلب والنتيجة
1. [assumption] يثبت الطلب الراوتر والمصدر ومعرف الكرت أو الجلسة والعملية والقيم الآمنة. تغيير الراوتر لا ينقل تأكيدًا قديمًا للوجهة الجديدة.
2. [assumption] يوضح أثر الإجراء ثم يطلب تأكيدًا منفصلًا للكتابة؛ الصلاحية والإمكان يعاد التحقق منهما عند التنفيذ، لا من ظهور الزر فقط.
3. [assumption] تظهر حالة الإرسال ثم القراءة المؤكدة. رفض الطلب يعرض سببًا ولا يغير بيانات الواجهة إلى النجاح.
4. [assumption] عند فقد الرد يبقى «بانتظار التحقق»، ويمنع تكرار الأثر حتى تسوية النتيجة. «تحقق» قراءة/تسوية للطلب نفسه، لا زر لإعادة أمر الكتابة.
5. [assumption] يبقى الطلب المعلق مرتبطًا براوتره عند الخروج والعودة؛ لا معالجة خلفية صامتة أو أمر مؤجل ينفذ على شبكة أخرى.
6. [assumption] نجاح الإجراء يعكس النتيجة التي قرئت؛ إذا لم تدعم نسخة الخدمة تحقق الفصل أو تعطيل الحساب كما توقعنا، يظهر القيد ولا يختلق تحققًا.

## الحالات والصلاحيات
- [assumption] قراءة فقط أو انقطاع يفسران عدم إتاحة التأكيد، مع بقاء الفحص والأرشيف. التحقق من طلب سابق قد يحتاج قراءة فقط حتى لو تغيرت صلاحية الكتابة.
- [assumption] اختفاء جلسة قبل الفصل يعالج كحالة تحتاج قراءة حديثة، لا فصل جلسة أخرى تشابه رقمها أو إعادة استخدام معرف قديم.
- [assumption] عدد الجلسات في الرأس والقائمة من المصدر والقراءة نفسها؛ لا تجمع مصادر متداخلة ولا يظهر عدد قديم بوصف «الآن».
- [assumption] لا حذف حسابات أو تغيير كلمة مرور أو إعداد خدمة بسبب إيقاف أو فصل؛ الإجراءات المؤثرة متعددة الخطوات تحتاج نتائج مستقلة بدل نجاح مجمع كاذب.
- [assumption] الرموز والأرقام ثابتة الاتجاه؛ نصوص الأفعال والحالات ثنائية اللغة مع مسافة وأهداف لمس وفق تجربة الجوال.

## شروط القبول
- [ ] [assumption] الفصل يستهدف الجلسة الصحيحة فقط، والإيقاف لا يختلق فصلًا، والإتاحة لا تجدد الرصيد.
- [ ] [assumption] تعارض الرقم بين نظامين وتبديل الراوتر وتغير الجلسة بعد المراجعة لا يغير الهدف.
- [ ] [assumption] الرفض وفقد الرد وإعادة التحقق وتكرار النقر تختبر بعداد أو دليل طلب؛ لا أثر مكرر أو نجاح غير مؤكد.
- [ ] [assumption] حساب قراءة فقط لا ينفذ كتابة، والإجراءات المحاكاة لا تنسب توافقًا أو صلاحية لجهاز حقيقي.

## خارج النطاق
- [assumption] حذف جماعي، إرسال تلقائي، حجب كل الشبكة، مراقبة خفية، وتجاوز قيود الخدمة أو حساب الراوتر.
