# مواصفة الرئيسية وفحص الكرت لصاحب الشبكة

**الملخص:** [confirmed] حدد المؤسس مهام العودة: فحص كرت وسبب انتهائه، إضافة كرت واحد أو عدة كروت، ومعرفة المتصلين؛ المصدر: محادثة 2026-11-13.
[assumption] الرئيسية تقدم هذه المهام داخل مساحة الراوتر قبل الأرشيف والتصميم؛ حالات البيانات أهم من ازدحام الإحصائيات.

## المشكلة والهدف
- [assumption] تخفيف الشرح والمساعدة في P-003 وP-010 لـPER-001؛ [مرجع المشاكل](../01-discovery/problems.md).
- [confirmed] حدود تفسير الاستهلاك القديمة محفوظة في [تحليل الدعم](../01-discovery/voucher-support.md) و[أدلة البيانات](../01-discovery/network-owner-data-evidence.md)؛ لا تستبدل بتخمين من واجهة جديدة.
- [assumption] النجاح: يبدأ المستخدم إحدى مهامه الأساسية مباشرة من الرئيسية، ويفهم إن كانت الإجابة قراءة حالية أو قديمة أو غير متاحة.

## ترتيب الرئيسية المقترح
1. [assumption] اسم الراوتر وحالة الوصول ووقت آخر قراءة، مع رجوع واضح لقائمة الراوترات؛ تبقى سياسة الاختيار في [مواصفة الربط](mobile-router-spec.md).
2. [assumption] «فحص كرت» زر فقط يفتح إدخال الرقم والنتيجة؛ لا نموذج دائم في الرئيسية. البحث داخل الراوتر المختار، وإذا تكرر الرقم في نظامين تظهر النتائج بمصدرها بدل اختيار أحدهما بصمت.
3. [assumption] فعل «إضافة كروت» يفتح اختيار كرت واحد أو دفعة؛ الواحد يبدأ بالتوليد الافتراضي مع خيار رقم مخصص، والدفعة تعرض العدد. التنفيذ والتأكيد في [مواصفة الإصدار](mobile-issuance-spec.md).
4. [assumption] عدد الجلسات النشطة في المصدر المحدد؛ الضغط يفتح قائمتها. لا يساوي عدد الأشخاص أو كل أجهزة Wi-Fi، ولا تجمع Hotspot وUser Manager دون حل التداخل.
5. [assumption] الدفعة غير المكتملة عند وجودها تقدم استكمالًا واضحًا وفق [مواصفة الأرشيف](mobile-archive-spec.md)، ثم وصول ثانوي للدفعات وإعادة الطباعة والقوالب.
- [assumption] لا يجبر المستخدم العائد على رحلة إعداد أو تصميم قبل فحص كرت؛ أول تشغيل فقط يعرض [إعداد الحساب والشبكة](mobile-account-setup-spec.md).

## نتيجة فحص الكرت
- [assumption] الهوية: الراوتر والنظام والرقم والباقة الفعلية، ثم حالة الحساب ومصدر القراءة وتوقيتها. معرفة رقم الباقة وحدها لا تثبت حقوق كرت قديم.
- [assumption] ملخص مقروء للحجم المستهلك والمتبقي، والتنزيل والرفع، ووقت الاتصال المستخدم وحده، وتاريخ بداية ونهاية الصلاحية إذا توفر دليلهما؛ حدود بلا سقف تعرض «غير محدود» ولا تقسم على صفر.
- [assumption] إذا أثبتت القراءة بلوغ حد البيانات نقول «اكتمل حد البيانات»؛ إذا تزامن أكثر من حد تعرض الحدود المثبتة، ولا نجزم بأيها تسبب في الفصل دون دليل.
- [assumption] بلوغ وقت الاتصال وانتهاء الصلاحية والإيقاف أسباب مستقلة عن الحجم؛ لا تعرض الصلاحية المنتهية «سارية». يستخدم التقرير والقائمة والتفاصيل تفسيرًا مشتركًا، وتعلن القيم المفقودة أو السالبة والتعارض بين الحالة العامة والحدود بدل تحويلها إلى رصيد أو أهلية مؤكدة.
- [assumption] تفسير «ليش خلص بسرعة؟» يميز حقيقة الاستهلاك عن سبب النشاط؛ لا ينسبه لتطبيق أو تحديث أو شخص أو مشاركة حساب من إجمالي العداد وحده.
- [assumption] تاريخ جلسات متوفر يفتح عند الطلب مع إزالة التكرار؛ لا يمسح التطبيق سجل User Manager كاملًا عند كل بحث، ولا يولد رسمًا تاريخيًا من قراءة وحيدة.
- [assumption] الإجراءات التالية موضعية: [رد الزبون](mobile-voucher-report-spec.md)، [تجديد بمراجعة](mobile-voucher-renewal-spec.md)، أو [شكوى ومتابعة](mobile-complaints-spec.md)؛ لا تعويض أو كتابة تلقائية من مجرد الفحص.
- [assumption] الرجوع من التفاصيل يعيد سياق فتحها: البحث ومرشحاته أو قائمة الكروت وتصفية حالتها أو الجلسة المحددة أو الدفعة؛ يحفظ السياق هوية الراوتر ولا يعاد استخدامه بعد تبديل الشبكة.

## قائمة الكروت
- [confirmed] طلب المؤسس قائمة للكروت مع البحث والفلاتر وفتح الكرت وإجراءاته؛ المصدر: محادثة 2026-11-13.
- [assumption] وجهة «الكروت» ثابتة في التنقل؛ القائمة ضمن الراوتر، وتبحث بالرقم وتصفّي الحالة والنظام والباقة عند الحاجة. يظهر المصدر مع كل رقم حتى إن تشابهت الأرقام.
- [assumption] الحالة تفرق بين لم يستخدم، ونشط بحسب دليل الخدمة، ومنتهي الرصيد، وموقوف، ومجدد جاهز؛ «متصل الآن» يحتاج جلسة حديثة ولا يستنتج من وجود رصيد.
- [assumption] العدد بعد التصفية منفصل عن العدد الكلي؛ صفحات أو تحميل إضافي يحفظ البحث ولا يضغط الراوتر بقراءة سجل كامل في كل ضغطة. الفشل يختلف عن صفر نتائج.
- [assumption] صف الكرت يفتح نفس التفاصيل والمشاركة والتجديد والشكوى، دون إعادة إدخال رقمه أو نقله إلى مصدر آخر.
- [assumption] «تجديد» و«إجراءات» ظاهران على الصف، وإجراءات الجلسة تظهر على صفها؛ دلالات الإيقاف والفصل والتأكيد في [مواصفة الإجراءات](mobile-quick-actions-spec.md).

## شرح مصدر الحسابات
- [confirmed] طلب المؤسس تعريف Hotspot وUser Manager للمستخدم الجديد بدل افتراض فهم المصطلحين؛ المصدر: محادثة 2026-11-13.
- [assumption] الشرح وقت اختيار الباقة أو التجديد أو فهم قائمة الكروت: «حسابات Hotspot المحلية» للكروت ضمن حسابات الراوتر المحلية، و«User Manager» لإدارة المستخدمين والباقات عبر RADIUS وقد يخدم صفحة Hotspot نفسها.
- [confirmed] Hotspot يدعم الحساب المحلي أو خادم RADIUS، وUser Manager خادم RADIUS؛ [توثيق Hotspot](https://help.mikrotik.com/docs/spaces/ROS/pages/56459266/HotSpot%2B-%2BCaptive%2Bportal)، [توثيق User Manager](https://help.mikrotik.com/docs/spaces/ROS/pages/2555940/User%2BManager)، مراجعة 2026-11-13. لذلك لا تعرض الواجهة النوعين كشبكتين لا تجتمعان، ولا تخلط مصدر الحساب بخدمة الوصول.
- [assumption] المصدر المعروف يحدد مسبقًا، والمساعدة قابلة للفتح والعودة؛ لا اختبار معرفة تقنية قبل بدء المهمة.
- [assumption] عند تكرر الرقم، يتوفر الشرح في شاشة الاختيار نفسها مع قرائن الباقة والحالة والمتبقي ومرجع الدفعة إن توفر. غياب مرجع الأرشيف معلن، ولا يختلق تاريخ إصدار ولا يختار مصدرًا أو يجمع رصيدًا بالتخمين.

## حالات لا تختزل إلى صفر
| الحالة | النتيجة المقترحة [assumption] |
|---|---|
| اتصال قائم وقراءة مكتملة بلا جلسات | صفر جلسات لهذا المصدر مع وقت القراءة |
| مهلة أو رفض صلاحية | تعذر الفحص؛ السبب وخطوة الإصلاح؛ لا «الكرت غير موجود» |
| قراءة كاملة لم تجد الرقم | لم يوجد في هذا الراوتر والنظام؛ مراجعة الرقم أو المصدر |
| الراوتر غائب مع محفوظ | قراءة سابقة مؤرخة؛ الحالة الحالية غير معلومة |
| لا سجل قديم | لا تتوفر بيانات كافية لتحديد السبب |
| عداد صفر بعد إعادة ضبط | لا يستنتج عدم الاستخدام أو استرجاع الرصيد دون دليل |
| جلسة أو محاسبة متأخرة | القراءة جزئية/متأخرة؛ لا إجمالي مكتمل وهمي |
| User Manager غير مثبت | حالة عدم توفر صريحة بدليل قدرات، لا صفر كروت |

## الصلاحيات واللغة
- [assumption] فحص الكرت والمتصلين قراءة فقط بصلاحيات الحساب المتصل؛ لا يوسع وصول المالك خارج مساحة الراوتر.
- [assumption] رقم حساب Mikro في حالة مراجعة لا يمنح صلاحية RouterOS ولا يمنع قراءة محلية مخولة.
- [assumption] لا تعرض الأسرار في البحث أو قائمة الجلسات؛ الأرقام لاتينية وتحفظ الأصفار البادئة، والأفعال تدعم العربية والإنجليزية والتكبير.
- [assumption] تلميحات قصيرة بجانب الوقت والصلاحية ومصدر الاستهلاك؛ التفاصيل تفتح عند الحاجة، لا جولة تعليمية إجبارية. مرجع التصميم [NN/g للمساعدة السياقية](https://www.nngroup.com/articles/onboarding-tutorials/)، مراجعة 2026-11-13.

## شروط القبول
- [ ] [assumption] من الرئيسية يمكن بدء الفحص أو كرت واحد أو دفعة دون المرور بتصميم قالب.
- [ ] [assumption] فحص يفتح مدخله عند الطلب، والإضافة تمر باختيار واحد/دفعة من فعل موحد؛ قوائم الكروت وفلاترها تحفظ السياق وتعالج عدم وجود نتائج.
- [ ] [assumption] اسم كرت متكرر في راوترين أو نظامين لا يخلط النتائج، ولا يتحول فشل القراءة إلى عدم وجود.
- [ ] [assumption] المعاينة تختبر حد بيانات وحد وقت وصلاحية وإيقافًا وغياب سجل وتضارب قراءات وأصفارًا بادئة.
- [ ] [assumption] عدد المتصلين يطابق قائمة المصدر نفسه ووقتها، ويصبح «آخر قراءة» عند الانقطاع.
- [ ] [assumption] تغييرات الوضع المحلي/البعيد لا تعيد إصدار كرت، ولا تسبب قراءات متراكمة أو مسح تاريخ ثقيل.

## خارج النطاق
- [assumption] معرفة استخدام تطبيقات أو مواقع من عدادات إجمالية، إثبات هوية جهاز/شخص، محاسبة المبيعات، وتنفيذ إجراءات معالجة غير معتمدة.
