# تحليل الباقات وإصدار دفعات الكروت

**الملخص:** مسودة تحليل ضمن خطة دورة الكرت المعتمدة؛ لا تمثل مواصفات أو قواعد تشغيل معتمدة.
الاحتياجات أصلها وصف المؤسس، والتوصيات موسومة [assumption]؛ ما يحتاج جواباً يبقى مفتوحاً.

## المرجع
- إعدادات الإصدار التي طلبها المؤسس في [مصدر الاحتياجات](network-owner-workflows.md). [confirmed]
- هذا الملف يحلل قواعد غير محسومة؛ جميع السياسات التالية [assumption] ومقترحة فقط.

## المحسوم مع المؤسس (2026-11-05) [confirmed]
- الوجهة: **الاثنان معاً** — بعض شبكات المؤسس تعمل على User Manager وأخرى على hotspot users المحليين؛ المنصة تدعم الوجهتين. [confirmed]
- بداية الصلاحية: **موحدة لكل الفئات** بنفس القاعدة الموثقة في [مصدر الاحتياجات](network-owner-workflows.md#الباقات-والنقاط-confirmed-المؤسس). [confirmed]
- البادئة واللاحقة: **مختلطة** — بعض الدفعات للدلالة البصرية وبعضها يرمز لمعلومات. [confirmed]
- الكروت الخاطئة أو المضروبة: المعالجة **حسب الحالة**، لا قاعدة عامة واحدة. [confirmed]

## قواعد مشتقة من المحسوم [assumption]
- دعم الوجهتين يعني توحيد الحسابات والقوائم والجرد فوق فرق بين نظامين، لا اختيار نظام واحد.
- البداية الموحدة تبسط شرح الكرت للزبون، لكن ملف كل فئة يذكرها صراحة بدل الاستنتاج من نوع الفئة.
- في البادئة المختلطة، لا تعتمد المنصة الرمز وحده لإثبات توزيع أو نقطة بيع؛ الترميز أداة مساعدة فقط.
- "حسب الحالة" للكروت الخاطئة يحتاج تدفقاً بموافقة صاحب الشبكة وإثبات النتيجة، لا استبدالاً آلياً.

## ما يجب فهمه قبل الإصدار [assumption]
| المعنى | ما يجب تحديده | الخلط الذي نمنعه |
|---|---|---|
| السعر | سعر الزبون وسعر توريد النقطة والعمولة إن وجدت | سعر التوريد ليس بالضرورة سعر البيع |
| الحجم | تحميل فقط أم تحميل ورفع؛ وحدة الحساب | نسبة استهلاك بمقام غير معلوم |
| وقت الاستخدام | مجموع مدة الجلسات وما يحدث مع التزامن | الخلط مع مدة الصلاحية التقويمية |
| الصلاحية | تبدأ من الإنشاء أو الإسناد أو أول استخدام | نفاد كرت لم يستخدم بسبب قاعدة غير معلنة |
| السرعة | رفع وتحميل وحدود معلنة | الخلط مع السرعة المقاسة فعلياً |
| نافذة الاستخدام | ساعات وأيام ومنطقة زمنية | الخلط مع موعد بيع العرض |
| التزامن | عدد الجلسات ومشاركة الكرت | سياسة مشاركة لم يعرفها الزبون |

## رحلة الإصدار المقترحة [assumption]
| خطوة | المنفذ والمدخل | النتيجة ودليلها | فشل أو تراجع |
|---|---|---|---|
| تحديد الهدف | صاحب الشبكة: الشبكة ونظام الدخول والباقة | مراجعة تعريف الباقة في النظام المستهدف | أي تعارض يوقف الإرسال لحين المراجعة |
| تجهيز الرموز | صاحب الشبكة: العدد والنمط والبادئة واللاحقة | معاينة تركيب وطول دون حفظ بيانات دخول حقيقية في docs | ضبط التركيب قبل إصدار حسابات |
| مراجعة الدفعة | صاحب الشبكة: ملخص الإعداد | تأكيد العدد والباقة والوجهة | إلغاء المسودة دون أثر على الراوتر |
| الإنشاء | عملية الإصدار بعد التأكيد | عدد مؤكد قابل للقراءة في الوجهة | عدم تكرار الإرسال الأعمى بعد الانقطاع |
| تسوية الجزء المفقود | صاحب الشبكة؛ مهندس عند عائق | تمييز موجود وغير موجود وغير معلوم | طلب التحقق قبل استكمال غير المعلوم |
| الإغلاق | صاحب الشبكة | الدفعة جاهزة للطباعة حسب نتيجة التحقق | الدفعة الجزئية لا توصف بالمكتملة |

## حالات الفشل التي يلزم تحليلها [assumption]
- ضغط زر الإنشاء مرتين أو إعادة الطلب بعد انتهاء مهلة الاتصال: نفس العملية لا تصبح دفعتين تلقائياً.
- رمز موجود مسبقاً أو أضافه شخص مباشرة في الراوتر: كشف التعارض، لا استبدال حساب قديم.
- العدد المطلوب تجاوز المتاح في البيئة: توضيح القيد قبل العملية إن أمكن، دون اختراع حد موحد للأجهزة.
- تغيير باقة أو حذفها في النظام الآخر أثناء الإنشاء: وقف وتسوية الاختلاف قبل الاستكمال.
- حساب ظهر في نظام الدخول دون أن يصل تأكيده: حالة غير محسومة، لا فشل مؤكد ولا نجاح شامل.
- الإنشاء في وجهة خاطئة: لا حذف تلقائي لدفعة بدأت تستخدم؛ مراجعة منفصلة لكل أثر.
- اختلاف الوقت بين الأجهزة: توثيق مصدر الوقت قبل تفسير انتهاء الباقة.
- الأصفار الأولى وحالة الحروف والمسافات والرموز غير المدعومة قد تغير قبول الدخول أو تمييزه؛ يلزم التحقق من النظام المستهدف لا التنسيق البصري فقط.
- إعادة استخدام رمز من دفعة ألغيت قد تجعل نسخة ورقية قديمة صالحة مجدداً؛ سياسة إعادة الاستخدام تحتاج حسم المؤسس.

## الإلغاء والحذف والإيقاف [assumption]
| حالة الدفعة | اقتراح للمراجعة | ما يبقى محفوظاً |
|---|---|---|
| مسودة لم تصدر | إلغاء المسودة | أثر العملية عند الحاجة للمراجعة |
| صدرت ولم توزع أو تستخدم | إلغاء حساباتها بعد تحقق النتيجة | رقم الدفعة وسبب الإلغاء |
| طبعت | إلغاء أو إيقاف مع تحذير من نسخ الورق | سجل الطباعة وإعادة الطباعة |
| وزعت أو ارتبطت بمال | معالجة التوزيع والتسوية قبل الإغلاق | الاستلام والحركات المالية |
| استخدم بعضها | فصل غير المستخدم عن المستخدم | الجلسات والحقوق والحركات السابقة |
- الإيقاف المطلوب لا يعني انتهاء جلسة نشطة فوراً؛ يجب التحقق مما يدعمه النظام وإثبات التنفيذ.
- تغيير الباقة لا يغير حقوق الكروت السابقة بصمت؛ الخيارات: حفظ الحقوق السابقة، أو تعديل معلن بشروط يوافق عليها المؤسس.

## أسئلة الحسم
المحسوم منها (2026-11-05): الوجهة (الاثنان معاً)، بداية الصلاحية (موحدة لكل الفئات)، البادئة (مختلطة)، الكروت الخاطئة (حسب الحالة). [confirmed]

- كيف يوثق "حسب الحالة" للكروت الخاطئة حتى لا يتكرر الجدل كل مرة، ومن يقرر كل حالة؟
- ما سياسة تغيير حقوق الكروت الصادرة إذا عدلت باقة لاحقاً؟
- الترجمة إلى إعدادات فعلية تحتاج التحقق حسب الإصدار (v6 مقابل v7) على راوتر حقيقي.
