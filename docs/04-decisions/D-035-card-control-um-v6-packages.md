# D-035 التحكم بالكروت، إصلاح User Manager v6، وقراءة الباقات

**الملخص:** صاحب الشبكة يقدر يغيّر كلمة سر الكرت أو اسمه، يوقفه ويشغله، يفصله، أو يحذفه من التطبيق (Hotspot وUser Manager v6/v7).
الأوامر مهام ثابتة ينفذها سكربت الراوتر نفسه (نفس طريقة إعادة التشغيل في [D-033](D-033-alerts-watcher-and-router-tasks.md))، بدون حفظ أي كلمة سر للراوتر.
User Manager v6 صار يُقرأ، والباقات تعرض السعر والمدة والسرعة وعدد الأجهزة بكلام صاحب الشبكة.
[confirmed] اعتمد المؤسس الخطة بتاريخ 2026-11-11.

## السبب
- [confirmed] المؤسس: لا يستطيع تعديل الكرت ولا معرفة من المتصل من قائمة الكروت؛ وUser Manager على راوتر v6 يظهر «غير مفعّل» مع أنه مفعّل.
- [confirmed] السبب: أمر الربط كان يقرأ User Manager على v7 فقط (`/user-manager`)، بينما v6 تحت `/tool user-manager` بحقول مختلفة (`username`, `actual-profile`, `uptime-used`).

## القرار
- [confirmed] أوامر الكرت الثابتة فقط: كلمة السر، الاسم، إيقاف، تشغيل، فصل، حذف. الرد بصيغة `card|job|source|action|name|value`.
- [confirmed] الأسماء والقيم تُفحص في الخادم: حروف إنجليزية وأرقام و`. _ @ -` فقط، حتى 32. لا يمكنها كسر أمر RouterOS.
- [confirmed] الأمر يُرفض إذا الراوتر غير متصل، ويُلغى إذا لم يستلمه خلال 5 دقائق، فلا يتغير شيء متأخراً بالمفاجأة.
- [confirmed] كلمة السر الجديدة تُمسح من قاعدة البيانات لحظة تسليمها للراوتر. تظهر لصاحب الشبكة مرة واحدة للنسخ أو الإرسال.
- [confirmed] User Manager: سكربت قراءة لكل إصدار (v6 تحت `/tool`، v7 مع `user-profile` لباقة كل كرت وحالته). التقرير يرسل هل الحزمة مثبتة ومفعلة وهل سكربت القراءة موجود، فالشاشة تفرّق بين: غير مثبت، مطفي، يحتاج إعادة ربط، يعمل.
- [confirmed] المتصلون الآن: التقرير (كل 30 ثانية) يرسل قائمة مختصرة لمتصلي Hotspot، وسكربت الكروت يرسل القائمة كاملة كل 5 دقائق، وسكربت User Manager يرسل جلساته.
- [confirmed] الباقات: نقرأ السعر والمدة وسعر البيع من سكربت الدخول بصيغة Mikhmon (`:put (",rem,1000,1d,1200,,Disable,")`) على الخادم فقط؛ ونقرأ حدود User Manager (السرعة، الوقت، البيانات). التفاصيل التقنية مخفية تحت «تفاصيل للمهندس».
- [confirmed] «بدأ اليوم» يُحسب من أول لحظة نرى فيها الكرت بدأ يُستخدم (يُسجل في قاعدة البيانات)، وليس من سجل الراوتر.

## الأدلة
- [confirmed] RouterOS 6.49.17 (CHR) مع حزمة user-manager: وصلت كروت Hotspot وUser Manager وباقاتهما مع الحدود وسعر Mikhmon. نُفذت أوامر: كلمة سر، اسم، إيقاف (Hotspot وUM v6)، ورُفض اسم مستخدم مسبقاً بنتيجة `exists`.
- [confirmed] RouterOS 7.16.2 (CHR) مع user-manager: `umi = pkg,true`، وصلت باقة كل كرت وحالته (`running`)، والحدود.
- [confirmed] User Manager يحفظ السعر بأجزاء المئة على v6 وv7 (3000 تُقرأ 300000)، فالسكربت يقسم على 100.

## حدود معروفة
- [assumption] كروت User Manager v7 لا تعطي الوقت والبيانات المستهلكة بدون أمر `monitor` لكل كرت (ثقيل)، فنعرض حالتها فقط.
- [assumption] الراوترات المربوطة قبل هذا القرار تحتاج «إعادة الربط» مرة لتحصل على السكربت الجديد؛ الشاشة توضح ذلك.
- إضافة كروت جديدة وطباعتها خارج هذا القرار.

## خيارات مرفوضة
- حفظ مستخدم كتابة على الراوتر للتحكم عبر API — رُفض: يخزن صلاحية كتابة عندنا ولا يعمل خلف NAT.
