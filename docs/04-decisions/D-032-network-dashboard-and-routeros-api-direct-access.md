# D-032 لوحة الشبكة والاتصال المباشر عبر RouterOS API

**الملخص:** الإعداد صار «أضف شبكتك»، واللوحة الرئيسية تراقب الشبكة والكروت بدل الراوترات، والاتصال المباشر صار عبر API (8729 ثم 8728) تلقائياً.

## القرار
- [confirmed] سبب «غير قابل للاتصال» على المنفذ 8728: التطبيق كان يحاول HTTPS (REST) على منفذ API. اختبرنا 8728 على راوتر المؤسس: يرد ويطلب تسجيل الدخول؛ مستخدم mikro-read غير موجود، فيلزم «إعادة الربط» مرة.
- [confirmed] الترتيب: 8729 مشفّر أولاً، ثم 8728 بمستخدم قراءة فقط. يعمل على v6 (6.43+) وv7. بطلب المؤسس يُعاد فتح رفض «اتصال غير مشفر» في D-031 لـ 8728 فقط كبديل.
- [confirmed] الراوتر يرسل منافذ api وapi-ssl وحالة NAT؛ نتصل تلقائياً بدون أسئلة، ونحدّث الكروت كل 5 دقائق مع كل تقرير.
- [confirmed] خلف NAT: سكربت mikro-cards يرسل كروت Hotspot كل 5 دقائق بدفعات 40، وmikro-um كروت User Manager (v7 فقط حيث الحزمة مثبتة).
- [confirmed] الإعداد: أنت ← الشبكة (الاسم والمدينة) ← الراوتر ← تم. إضافة راوتر لاحقاً من قسم «الشبكة».
- [confirmed] اللوحة: الرئيسية (متصلون، كروت جديدة، قيد الاستخدام، الراوترات)، الكروت (بحث وحالات وباقات وتفاصيل)، النشطون، الشبكة. شريط سفلي في الجوال.
- [confirmed] لا نخزن كلمات مرور الكروت.

## خارج النطاق
- إضافة وطباعة الكروت فعلياً تحتاج صلاحية كتابة؛ قرار أمني منفصل. تظهر «قريباً».
- استهلاك كروت User Manager خلف NAT (v7 لا يعطيه في قائمة المستخدمين) وUser Manager على v6 خلف NAT.

## المخاطر
- [assumption] الأمر صار أطول (~7000 حرف)؛ قد يقطعه تطبيق الجوال. يُختبر على راوتر حقيقي.
- [assumption] اتصال TCP المباشر من الخادم بعد النشر يحتاج تأكيد على راوتر حقيقي.
