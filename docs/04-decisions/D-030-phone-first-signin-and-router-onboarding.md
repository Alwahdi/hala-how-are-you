# D-030 الدخول برقم الجوال أولاً ومعالج أول راوتر

**الملخص:** الدخول يبدأ برقم الجوال ورمز WhatsApp، ثم Google أو البريد، ثم معالج يضيف أول راوتر بطريقتين: أمر اللصق (موصى به) أو IP Cloud.
وافق المؤسس على الخطة 2026-11-11. [confirmed]

## القرار
- [confirmed] الرحلة: الجوال ← رمز من 6 أرقام على WhatsApp (10 دقائق، 5 محاولات، 3 إرسالات كل 10 دقائق) ← Google/البريد ← معالج أول راوتر.
- [confirmed] المستخدم العائد يدخل مباشرة بدون رمز. «المتابعة بدون رمز» تظهر فقط حين تكون خدمة الرمز غير مفعلة.
- [confirmed] IP Cloud متاح لـ v7 فقط في هذه المرحلة: مستخدم قراءة فقط، شهادة Let's Encrypt عبر IP Cloud، REST على HTTPS، والسر مشفر لدينا. يُحدَّث فقط أثناء فتح صفحة «راوتراتي».
- [confirmed] عند فشل IP Cloud (CGNAT أو منفذ مغلق) يُقترح أمر اللصق بضغطة.

## خيارات مرفوضة
- رمز SMS: تكلفة وتوصيل غير مضمون في اليمن وسوريا.
- IP Cloud لـ v6 الآن: يحتاج بروتوكول API (8729) بشهادة موقعة ذاتياً لا يقبلها الخادم؛ مؤجل.

## مخاطر مفتوحة
- [assumption] قالب WhatsApp للرمز يحتاج موافقة Meta وله تكلفة لكل رسالة.
- [hypothesis] إصدار شهادة Let's Encrypt من الراوتر يتطلب وصول المنفذ 80؛ لم يُختبر على راوتر حقيقي.
- فتح 443 يوسع سطح الهجوم؛ نوصي بتقييده في الجدار الناري.

## تحديث 2026-11-11: أمر لصق بسطر واحد ومعرفة الإصدار تلقائياً
- [confirmed] تطبيق Terminal في الجوال حذف فواصل الأسطر فظهر `expected end of command (line 1 column 50)` (صورة من المؤسس).
- القرار: أمر اللصق صار سطراً واحداً قصيراً (`/tool fetch` لملف إعداد ثم `/import`)، مع أمر بديل كامل في سطر واحد بفواصل `;`.
- لا يُسأل المستخدم عن إصدار RouterOS؛ يُعرف من أول تقرير أو من اتصال IP Cloud.
- [assumption] شهادة HTTPS قد تفشل على بعض راوترات v6 القديمة؛ يحتاج تجربة على راوتر حقيقي.
