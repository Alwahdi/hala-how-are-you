# D-031 الاتصال المباشر التلقائي ولوحة الراوترات ونوع الحساب

**الملخص:** المؤسس طلب ما يكتب اسم IP Cloud ولا المنفذ أبداً، ولوحة تناسب صاحب شبكة عنده راوتر أو اثنين، وبيانات المدينة واسم الشبكة ونوع الحساب عند التسجيل.

## القرار
- [confirmed] السكربت يرسل العنوان العام (IP Cloud public-address) ويقارنه بعناوين الراوتر: لو موجود على منفذ = مش خلف NAT. عندها، مع v7 وIP Cloud وHTTPS شغال، نتصل مباشرة تلقائياً مرة واحدة، والإشارات (push) تبقى احتياط.
- [confirmed] خلف NAT لا نعرض أي شي عن IP Cloud. إدخال الرابط والمنفذ يدوياً صار في «متقدم» فقط.
- [confirmed] سبب فشل ربط «شبكه تواصل»: خدمة HTTPS (www-ssl) مطفية في الراوتر (`sslDisabled=true`). نعرض أمر تفعيل HTTPS بسطر واحد بدل نموذج الرابط.
- [confirmed] تنظيف المدخلات: يشيل http(s)://، www.، المسار، المسافات، ويحوّل الأرقام العربية.
- [confirmed] النسخ يضيف سطراً جديداً فيتنفذ الأمر عند اللصق (بعض تطبيقات الجوال قد تحذفه، فيبقى Enter مرة).
- [confirmed] شاشة «أهلاً» لأول مرة: صاحب شبكة / مهندس، اسم الشبكة، المدينة. الدور يحفظ في جدول أدوار منفصل عبر الخادم.
- [confirmed] اللوحة: ملخص (متصل، مستخدمو الهوتسبوت، تنبيهات)، دور لكل راوتر (عام / دمج خطوط / توزيع)، مقاييس بصرية.

## المرفوض
- تفعيل HTTPS تلقائياً داخل أمر الربط: يفتح خدمة ويب على الإنترنت بدون علم المالك.
- الاتصال بـ REST عبر HTTP بدون تشفير: يرسل بيانات الدخول مكشوفة.
