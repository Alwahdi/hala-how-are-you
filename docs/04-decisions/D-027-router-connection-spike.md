# D-027: تجربة أول ربط حقيقي براوتر MikroTik

**الملخص:** نبدأ ربط الراوتر بتجربة محدودة تقرأ حالة الراوتر العامة فقط من راوترين (v6 وv7). الاتصال يبادر به الراوتر نحو خادم Mikro مستقل (VPS) ليتجاوز CGNAT. القراءة بمستخدم للقراءة فقط، ولا تُحفظ كلمات مرور. ملاحظات الواجهة المؤجلة لا تُلغى.

## السياق
- [confirmed] الشبكات خلف CGNAT وبإصدارات v6 وv7 ([H-005/H-008](../01-discovery/hypotheses.md)).
- [confirmed] المؤسس يملك راوتر v6 وراوتر v7 للتجربة، ووافق على استئجار VPS (2026-11-11).
- [confirmed] أول قراءة مطلوبة: حالة الراوتر العامة.

## القرار
- اتصال صادر من الراوتر: WireGuard في v7، وSSTP في v6 (مع L2TP/IPsec بديلاً).
- خادم مستقل يحتفظ بالأنفاق، لأن الموقع الحالي (Workers) لا يحتفظ باتصالات دائمة. [confirmed]
- القراءة عبر RouterOS API داخل النفق فقط، بمستخدم مجموعة `read`.
- التفاصيل والمراحل ومعايير النجاح في [خطة التجربة](../03-product/router-connection-spike.md).

## خيارات مرفوضة
- الدخول عبر IP Cloud/DDNS أو IP ثابت: لا يعمل خلف CGNAT.
- طلب كلمة مرور المدير من صاحب الشبكة: يخالف الأمان والثقة.
- تشغيل الأنفاق داخل الموقع الحالي: غير ممكن تقنياً.

## الأثر الاقتصادي
- [assumption] تكلفة الخادم 5–10$ شهرياً في التجربة؛ لم يتم التحقق من الأسعار.
- لا إيراد من هذه المرحلة؛ قيمتها إزالة أكبر خطر تقني قبل أي ميزة مدفوعة.
