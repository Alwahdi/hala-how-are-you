# D-033 تنبيهات الجوال، المراقب الخلفي، وصحة الراوتر وإجراءاته

**الملخص:** تنبيهات جوال (Web Push) بدون حساب خارجي، ومراقب يعمل كل دقيقة، وفحص صحة للقراءة فقط، وإجراءات (إعادة تشغيل، حذف الكروت المنتهية) تمر عبر قائمة مهام ثابتة ينفذها سكربت الراوتر نفسه.
[confirmed] اختيارات المؤسس: قناة «تنبيه جوال» فقط؛ كل الأحداث الأربعة؛ «تلقائي للمهام الآمنة».

## القرار
- [confirmed] التنبيهات: معيار Web Push (VAPID) مشتق من سر خادم واحد؛ iPhone يحتاج «إضافة للشاشة الرئيسية» (شرط Apple).
- [confirmed] المراقب كل دقيقة: انقطاع بعد 3 دقائق ورجوع، ضغط (CPU > 90% لثلاث قراءات، ذاكرة > 90%، حرارة > 70، إعادة تشغيل مفاجئة) مرة كل ساعة كحد أقصى، نقص الكروت (< 20 جاهز في باقة فيها 30+) مرة يومياً، تقرير يومي 21:00 بتوقيت المالك.
- [confirmed] صحة الراوتر للقراءة فقط مبنية على [الأعطال الشائعة](../06-mikrotik/common-faults.md): المساحة، الذاكرة، مزامنة الوقت وتاريخ الراوتر، الإصدار وثغرة Winbox، telnet/ftp، socks/proxy، عدد المستخدمين، idle-timeout، shared-users.
- [confirmed] الإجراءات: لا نخزن أي كلمة سر بصلاحية كتابة. رد تقرير الراوتر يحمل مهمة واحدة بصيغة ثابتة (`reboot|` أو `rm|id|names`)، والسكربت لا ينفذ غير هاتين. الراوتر يتحقق بنفسه أن الكرت منتهٍ قبل حذفه.
- [confirmed] التلقائي: حذف كروت Hotspot المنتهية منذ 3 أيام (قابل للتغيير) الساعة 3 فجراً مع تقرير. إعادة التشغيل لا تكون تلقائية أبداً.

## خيارات مرفوضة
- مستخدم API بصلاحية write للتحكم المباشر عبر الإنترنت — رُفض لأن سياسة write في RouterOS عامة ولا تُحصر بقائمة.
- Firebase/FCM — رُفض لأنه يحتاج حساباً خارجياً من المؤسس بلا فائدة إضافية.
- WhatsApp/Telegram/البريد — غير مختارة الآن.

## حدود معروفة
- [assumption] أمر اللصق صار ~11 ألف حرف؛ لو قصّه تطبيق الجوال نقسمه.
- [assumption] حذف كروت User Manager لم يُبنَ (Hotspot فقط).
- نصوص التنبيهات بالعربية فقط حالياً.
