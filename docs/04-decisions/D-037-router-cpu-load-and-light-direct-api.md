# D-037 تخفيف ضغط المعالج (CPU) على الراوتر واتصال API خفيف

**الملخص:** سكربتاتنا كانت ترفع معالج راوتر المؤسس (RB2011، v6.49.17، أكثر من 3,000 كرت User Manager) إلى 100%.
صار السكربت لا يبدأ وهو شغال، ويقرأ القائمة بطلب واحد، ويقرأ الكروت كاملة كل 30 دقيقة للشبكات الكبيرة، ولا يفحص سجل جلسات User Manager أبداً.
الاتصال المباشر عبر API صار فحصاً خفيفاً (دخول + 3 قراءات سريعة) ونجح على منفذ المؤسس 8778 خلال 1.2 ثانية.
[confirmed] اعتمد المؤسس الخطة بتاريخ 2026-11-11.

## السبب
- [confirmed] المعالج كان 2–3% قبل 06:46 يوم 2026-11-11، وصار يصل 100% بعد إعادة الربط (سجل الحالة كل 5 دقائق).
- [confirmed] قراءة كروت User Manager كانت تأخذ حوالي 10 دقائق، والسكربت يبدأ كل 5 دقائق، فتتراكم النسخ.
- [confirmed] تقرير الـ30 ثانية كان يفحص سجل جلسات User Manager كله ليعدّ المتصلين، وسكربت الكروت يفحصه كل 5 دقائق.
- [confirmed] منفذ 8778 مفتوح من الإنترنت، لكن فحص API كان يطلب كل كروت User Manager بمهلة 9 ثوانٍ للكل، فينتهي الوقت. والراوتر يكمل الحساب بعد انقطاعنا، والخادم يعيد كل 3–5 دقائق.
- [confirmed] سكربت Hotspot وسكربت User Manager يرسلان في نفس الوقت، فكان أحدهما يمسح تسجيل الآخر للدفعات. هذا يعطل حذف الكروت المختفية بأمان.

## القرار
- [confirmed] لا تراكم: كل سكربت يتوقف إذا وجد نسخة منه ما زالت تعمل. جُرّب على v6 وv7 (3 تشغيلات متتالية = تشغيل واحد).
- [confirmed] القائمة تُقرأ بطلب واحد (`print as-value`) بدل طلب لكل كرت: 9 ثوانٍ بدل 26 لـ3,048 كرت على v6 الافتراضي.
- [assumption] إذا جاءت القائمة لكرت مستخدم بدون أرقام الاستهلاك، يُقرأ هذا الكرت لوحده. لم نختبره لأن الكروت الافتراضية لم يدخل بها أحد. أسوأ حالة: سرعة السكربت القديم، كل 30 دقيقة وبدون تراكم.
- [confirmed] الكروت كاملة: كل 5 دقائق حتى 1,000 كرت، وكل 30 دقيقة فوقها. الباقات كل تشغيل.
- [confirmed] 100 كرت في كل إرسال بدل 40 (اتصالات مشفرة أقل)، مع توقف ثانية بعد كل إرسال.
- [confirmed] «المتصلون الآن» من قائمة Hotspot active فقط. كروت User Manager تدخل عبر Hotspot، فعلامة آخر اتصال تُسجل للكرت أياً كان نوعه.
- [confirmed] فحص API: دخول + معلومات الراوتر + المتصلون، بمهلة 8 ثوانٍ لكل خطوة. لا نقرأ User Manager عبر API أبداً. بعد الفشل ننتظر 30 دقيقة، و«جرّب الآن» تفحص فوراً.
- [confirmed] تسجيل دفعات الكروت صار عملية واحدة في قاعدة البيانات، ونحفظ مدة آخر قراءة كاملة. تظهر في صحة الراوتر، وتنبيه إذا زادت على 4 دقائق.

## خيارات رُفضت
- إبقاء قراءة كل الكروت كل 5 دقائق مهما كان العدد: ثقيل على الراوترات الضعيفة.
- عدّ متصلي User Manager من سجل جلساته: يكبر مع الوقت ويفحص كاملاً في كل مرة.

## حدود معروفة
- [assumption] كروت User Manager التي تدخل عبر PPPoE (لا Hotspot) لن تظهر في «المتصلون الآن». نادر في شبكات الكروت.
- [confirmed] استهلاك الكروت غير المتصلة يتحدث كل 30 دقيقة في الشبكات الكبيرة. الإجراءات من التطبيق (تجديد، إيقاف، حذف) تتحدث فوراً.

## التحقق
- [confirmed] v6.49.17 الافتراضي (3,048 كرت UM): القراءة الكاملة 85 ثانية مع الإرسال والتوقفات، وكل الكروت وصلت، والمدة سُجّلت (71 ثانية).
- [confirmed] v7.16.2: الكروت والباقات وحالة الباقة وتاريخ الانتهاء وصلت. الكروت التي لم تعد على الراوتر حُذفت بعد قراءة كاملة.
- [confirmed] راوتر المؤسس الحقيقي: الفحص الخفيف اتصل على 8778 خلال 1.2 ثانية والمعالج 100% وقتها.

## المتبقي
- النشر، ثم «إعادة الربط» مرة على الراوترين. الراوتر «الرئيسي» (v7) كلمة سر مستخدم القراءة عليه لا تطابق، وإعادة الربط تصلحها.
