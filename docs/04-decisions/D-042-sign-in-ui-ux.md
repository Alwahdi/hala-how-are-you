# D-042: تحسين واجهة الدخول وتجربتها

**الملخص:** [confirmed] اعتمد المؤسس خطة تحسين عرض الدخول والاستعادة وطرق الدخول بتاريخ 2026-11-12، دون تغيير قناة التحقق أو قواعد الهوية أو نشر التطبيق.

## السياق
- [confirmed] فحص المتصفح أظهر صفوف خيارات متنافسة وخلفية ظاهرة داخل الحقول ونموذج هاتف غير قابل للإرسال؛ المصدر: فحص الشاشة قبل التنفيذ في تاريخ القرار.

## القرار
- [confirmed] اختيار طريقة هادئ، عنوان بحسب المهمة، زر تنفيذ أساسي واحد ورابط سياقي لإنشاء الحساب؛ حقول مقروءة وإظهار كلمة المرور.
- [confirmed] الاستعادة رحلة منفصلة بصريًا عن خيارات الدخول؛ إظهار نتيجة الطلب وعدم تطابق تأكيد كلمة المرور وحالة الحفظ.
- [confirmed] الهاتف يظهر غير متاح مع رجوع للبريد، دون نموذج أو إرسال وهمي؛ عائق تشغيله يبقى في D-040 وD-041.
- [confirmed] قسم طرق الدخول يعرض الحالة أولًا، ويفتح تغيير البريد عند الطلب مع إلغاء وحالات تحميل وخطأ وانتظار التأكيد.

## الأسباب
- [assumption] تقليل التنافس البصري والمسارات المسدودة يخفف الالتباس؛ لا دليل تحويل أو اختبار مستخدم حقيقي ضمن هذه المهمة.

## البدائل المرفوضة
- [confirmed] نموذج هاتف مع زر معطّل: لا يطابق الإمكانات الحالية ويطلب بيانات دون نتيجة؛ استُبعد ضمن الخطة المعتمدة.
- [confirmed] تغيير قناة التحقق لإكمال التصميم: خارج نطاق التحسين ومتعارض مع القرار المرتبط.

## التحقق والحدود
- [confirmed] اجتازت اختبارات التوجيه والتحقق الهاتفي القائمة، 8 اختبارات؛ لا تغيير لقواعد الدخول أو كلمة المرور.
- [confirmed] فحص المتصفح باللغتين على 360/934/1280: لا تجاوز عرض؛ إنشاء الحساب وإظهار كلمة المرور والرجوع والاستعادة واختيار الهاتف تعمل بصريًا، ولا نموذج أو طلب عند اختيار الهاتف.
- [confirmed] فُتح تعديل البريد وأُلغي في حساب مصادق عليه، دون تقديم الطلب؛ لا أخطاء JavaScript خلال الفحص.
- [confirmed] فُحصت الاستعادة دون رابط صالح؛ لا عرض لنموذج تغيير كلمة المرور. لم تُرسل رسائل ولم يتغير الحساب، ولم تختبر استعادة حقيقية أو تأكيد بريد أو هاتف.
- [confirmed] لا نشر ولا عمليات راوتر؛ الخطوة التالية مراجعة المؤسس، واختبار الرسائل الفعلية عند اعتماد حساب ومستلم اختبار.
